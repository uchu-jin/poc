# プラン：骨格字形と輪郭生成

状態：承認済み（2026-11-22 作者）／プランレビュー・テストレビュー・実装レビュー（P1）の指摘を反映（2026-11-23） ｜ 元資料：docs/requirements/requirements.md（ストーリー1・2、FR-001、FR-005、FR-007、FR-011、FR-019、FR-020、SC-001、未確定事項 #4）
関連ADR：ADR-0001（採択）

## 1. 概要
英数 62 字（A-Z、a-z、0-9）とスペースの既定の骨格字形（中心線）と、骨格とパラメータから輪郭を組み立てる純粋な関数を作る。パラメータは太さ・横線の太さ（コントラスト）・幅・傾き・x ハイト・端の形・角の丸みの 7 つ（FR-002）。あわせて Vite + React + TypeScript のプロジェクトを初期化し、62 字を既定値と上限・下限で並べるだけの確認用ページを置く。輪郭を作れなかったときは例外を投げず、失敗と理由を結果として返す。骨格データは組み立ての入口で検査し、不正なものは組み立てない。

## 2. 背景
- 全機能の土台。A の変形画面（ストーリー1）、一覧（ストーリー2）、個別編集（ストーリー3）、カーニング（ストーリー4）、OTF 書き出し（ストーリー5）が、すべてこの関数を呼ぶ
- 輪郭の作り方は ADR-0001 で採択済み（自前の膨らませ＋端・角の図形＋clipper-lib で合成）
- 要件との対応：FR-001（既定の骨格と 1000 単位の座標）、FR-005（上限・下限で止まる）、FR-007（パラメータが全文字に効く）、FR-011（個別に直した骨格にもパラメータが効く。この機能では「差し替えた骨格を受け取れる」ところまで）、FR-019（x ハイト）、FR-020（横線の太さ）、SC-001（短時間で全文字が揃う）
- 未確定事項 #4（各パラメータの上限・下限の値）は、このプランの実装順 11 で決める
- 記号 32 字は別のプランにする（作者の回答 Q2）。仕組みはこのプランのものをそのまま使う

判断済みの論点：
- 輪郭の作り方は ADR-0001 に従う：自前で膨らませ、端・角の図形を足し、clipper-lib で合成する。座標は 10 倍の整数、塗り方は NonZero、輪郭の向きを揃えてから渡す。clipper-lib に渡す配列は毎回作り直す（V-12 の教訓）。`ADR-0001` のコメントは決定がコードに現れる expand.ts・terminals.ts・union.ts の 3 つに書き、ADR の「実装箇所」に足す
- パラメータは 7 つ（FR-002、作者の回答 Q3）：太さ（縦線の太さ）、横線の太さ、幅（横方向の倍率）、傾き（度）、x ハイト、端の形（平ら／丸／スラブ）、角の丸み（尖り／丸）
- コントラストは線の向きで連続的に変える（FR-020、Q5）：その点の線の向きが水平からの角度 θ のとき、太さ ＝ 横線の太さ ＋（太さ − 横線の太さ）×｜sin θ｜。O のような曲線も上下が細く左右が太くなる。丸い端・角の円の半径も、その点の太さの半分にする
- 逆コントラスト（横線の太さ > 太さ）は許す（2026-11-23 作者）。太さと横線の太さは、それぞれ独立に 20〜150（2026-11-23 に上限を 200 から 150 に決定）
- 太さが点ごとに変わる膨らませは ADR-0001 では検証していない（検証したのは太さが一定の場合）。実装中に、上限・下限の組み合わせテストで例外が出る、または速さのテストが基準を超えたら、実装を止めて作者に報告し、ADR-0001 の「見直す条件」に当たるかを判断してもらう
- x ハイトは区間ごとに伸び縮みさせる（FR-019、Q6）：小文字の骨格は基準の x ハイト 500 で書き、y が 0〜500 の点は 0〜x ハイトへ、500〜アセンダーの点は x ハイト〜アセンダーへ直線で写す。ディセンダー側（y < 0）とアセンダーより上（750 < y ≦ 1000）は動かさない（750 より上の扱いは仮置き：テストレビューで仕様の抜けとして挙がり、AI のおすすめを置いた。作者が変えてよい）。大文字と数字には効かない
- 幅は骨格の x 座標に倍率を掛けてから膨らませる（線の太さは変わらない）
- 傾きは、膨らませ・端・角の図形を作ったあと、合成の前に斜めにずらす（x ← x ＋ y × tan 傾き）。ADR-0001 の検証（spike.mjs・spike2.mjs・spike5.mjs）と同じ順番で、V-02・V-13・V-16 の結果をそのまま根拠にできる
- 線のつなぎ目（A の頂点、N の角など、線どうしがつながる端点）の処理（ADR-0001 の V-04 補足で約束したもの）：
  - 角の丸みが「丸」：つながる端点に、その点の太さの半分の半径の円を足す（V-07 と同じ）
  - 角の丸みが「尖り」：つながる 2 本の線の外側の辺を延長し、交点までを埋める多角形（miter）を足す。延長が太さの 4 倍を超える鋭い角は、外側の 2 点を結んで切る（bevel）。これで V-04 の頂点の切れ込みが消える
- 実装で決めたこと（2026-11-23 の実装レビューで記録が足りないと指摘され、ここに書いた）：
  - 膨らませは、線分ごとの帯を 2 つの三角形に分けて合成に渡す。1 本のリングだと太い線のきついカーブで内側に細い穴が残るため（ADR-0001 V-19）
  - 1 本の線の中で、区間の境目の向きが 20° を超えて曲がる所は、線を分けて「線どうしがつながる点」として扱う（尖り・丸の角が付く。L を 1 本の線で書いても角が埋まる）
  - 他の線の上にある端（T 字。横棒の端、T の縦線の上の端、e の横棒の端など）には、丸い端・スラブ・角のどれも付けない
  - 同じ点で同じ向きに離れていく端（同じ線を重ねた・同じ道を引き返した）は 1 つの端にまとめる。ほかに向きがなければ自由な端として端の形を付ける
  - 尖った角は、つながる端を向きの順に並べ、隣り合う組だけに付ける（組の数を端の数に比例させる）。交点が両方の線の後ろにあるときだけ miter（引数の順番によらない）
  - 1 文字を折れ線にしたときの点の数は 400 まで（`MAX_FLAT_POINTS`。既定の 62 字の最大は 130）。上限の中のどんな骨格でも組み立てが重くなりすぎないように
  - `buildGlyph` は想定外の例外も捕まえて「合成に失敗」として返す。パラメータが null のときは既定値で組み立てる。線がすべて長さ 0 のときは「輪郭が空」
- スラブは直線の端だけに水平に付ける（Q11）。曲線の終わりと、線どうしがつながる端点には付けない。寸法は厚み ＝ max（太さ × 0.45、12）、張り出し ＝ 端の中心から左右に 太さ × 1.4（V-07 の spike2.mjs と同じ。仮置き。作者が確認用ページで見て変えてよい）。張り出しは左右それぞれ、隣の線（スラブの高さの範囲にある他の線を太さの半分だけ太らせたもの）までの空きの 4 割までに縮める（2026-11-23 作者が決定。固定の張り出しだと a・b・d・g・p・q・r・1 で隣の線にぶつかり穴が増えたため）。水平から 30° 未満の直線の端にはスラブを付けない（実装時の判断）
- 文字幅は「輪郭の左右の端＋全文字共通の余白」（Q4）。輪郭の左端が余白の位置に来るように平行移動し、文字幅 ＝ 輪郭の幅＋余白×2
- スペースは骨格を持たない特別な文字として扱う。`buildGlyph` はスペースに対して `{ ok: true, outline: [], advanceWidth: スペースの幅, bounds: null }` を返す。「輪郭が空」の失敗は、スペース以外の文字の輪郭が空になったときだけ返す
- 返す輪郭の座標は 1000 単位（合成用の 10 倍を戻した値。小数第 1 位まで）。OTF に入れるときの整数への丸めは OTF 書き出しの機能で決める
- 上限・下限は固定（Q9）。数値の 5 つ（太さ・横線の太さ・幅・傾き・x ハイト）の上限・下限のすべての組み合わせ（32 通り）× 端と角の 6 通り × 62 字で、全文字の穴の数が想定どおりのままになる範囲にする
- `clampParams` は、数値パラメータの NaN を既定値に、Infinity を上限に、−Infinity を下限に丸める。端の形・角の丸みに未知の値が来たら既定値（平ら・尖り）にする（仮置き：テストレビューで挙がった抜けに AI が置いた。作者が変えてよい）
- 失敗は結果で返す（Q10）：`buildGlyph` は例外を投げず、`{ ok: true, outline, advanceWidth, bounds }` か `{ ok: false, reason }` を返す。reason は「骨格データが不正」「合成に失敗」「輪郭が空」の 3 つ。clipper-lib の例外（大きすぎる座標の RangeTest など）も捕まえて「合成に失敗」にする。画面側で直前の輪郭を出し続けるのは次の機能
- 骨格データは入口で検査する（docs/rules/security.md「保存データを読み込むときは、形を検証してから使う」）。個別に直した骨格は、のちに保存データ（FR-017）から入ってくるため。`validateSkeleton` が調べること：
  - 座標がすべて有限の整数で、x・y とも −250〜1000 の範囲（NaN・Infinity・小数は不正）
  - 点の ID が文字の中で一意
  - 線の区間の種類が既知のもの（直線・3 次ベジェ）だけ
  - 線が 1 本以上、各線の点が 2 つ以上
  - 1 文字あたり線 16 本まで、1 本あたり点 64 個まで（仮置き。極端に大きな骨格で処理が止まらないようにするため。既定の 62 字がこの中に収まることもテストする）
- 骨格データは TypeScript のデータとして書き、点ごとに文字の中で一意な ID を付ける。個別編集（ストーリー3）で「どの点を動かしたか」を指せるようにするため
- 個別に直した骨格は、基準の座標（x ハイト 500、幅 1.0、傾き 0）のまま差し替えとして `buildGlyph` に渡す。こうすると、直したあとに A でパラメータを変えても効く（FR-011）。保存の仕方は個別編集と自動保存の機能で決める
- `union` は clipper-lib のクリッパーを作る関数を省略可能な引数で受け取る（既定は本物の clipper-lib）。テストでは失敗するクリッパーを渡して「合成に失敗」を確かめる（docs/rules/architecture.md「テストでモックできるようにする」）
- 既定の字形は幾何学的なサンセリフ（Q8）：直線と円・楕円で作る
- 62 字の骨格は AI が下書きし、確認用ページで作者が見て、直したい文字を伝える（Q12）。形の最終判断は作者。このプランの中での直しは 2 回まで。3 回目以降に残った文字は、「文字ごとの骨格編集」の機能ができてから作者が直す（実装順 10 の完了の条件）
- 確認用ページ（Q7）は、既定値と「上限・下限の代表的な組み合わせ」で 62 字を並べる。操作はできない。外部の CDN・Web フォントなどの外部リソースは読み込まない（文字はシステムのフォント、字形は SVG）。A の変形画面ができたら置き換える
- clipper-lib を入れたら `npm audit` を回し、結果を実装順 1 の報告に貼る。high 以上が出たら、実装を止めて作者に報告する

## 5. 新規テストケース
単体（Vitest、`tests/glyph-engine/`）：
- 初期化：clipper-lib で重なった正方形 2 つを合成すると、輪郭が 1 つで面積が 17,500 になる（Vite／Vitest で clipper-lib が読み込めることの確認）
- `clampParams`（FR-005）：
  - 範囲内 → そのまま、下限ちょうど・上限ちょうど → そのまま
  - 太さ 19 → 20、20 → 20、150 → 150、151 → 150。傾き −1 → 0、16 → 15。横線の太さ・幅・x ハイトも同じく下限の 1 つ下・上限の 1 つ上で確かめる（幅は 0.79 → 0.8、1.26 → 1.25）
  - 5 つの数値パラメータそれぞれで NaN → 既定値、Infinity → 上限、−Infinity → 下限
  - 端の形・角の丸みに未知の値 → 既定値（平ら・尖り）（仮置き）
- `validateSkeleton`：
  - 正常な骨格 → 合格。下限ちょうど（線 1 本・点 2 つ）→ 合格
  - 座標が NaN／Infinity／小数 → 不正。x と y は別々に確かめる：x −251・y 0／x 1001・y 0／x 0・y −251／x 0・y 1001 → 不正、−250・1000 ちょうど → 合格
  - 点の ID の重複 → 不正
  - 未知の区間の種類 → 不正
  - 線が 0 本、点が 1 つの線 → 不正
  - 線 16 本・点 64 個ちょうど → 合格、線 17 本・点 65 個 → 不正
  - 形が崩れたデータ（保存データから来る想定。docs/rules/security.md）：`null`、`undefined`、線の配列がない、線の点が配列でない、点に `x` がない、`x` が文字列 "10" → どれも不正で、例外を投げない
- `flatten`：直線 1 本 → 両端の 2 点、3 次ベジェ 1 本 → 17 点（両端を含む）で始点・終点が一致、閉じた線 → 最後の点が最初と重複しない、直線のあとにベジェが続く線 → つなぎ目の点が 2 回入らない
- `verticalRemap`（FR-019）：
  - x ハイト 420（下限）：y 0 → 0、500 → 420、250 → 210、625 → 585（500〜750 の中間が 420〜750 の中間）、750 → 750、−100 → −100、−250 → −250
  - x ハイト 580（上限）：500 → 580、625 → 665、750 → 750、−100 → −100
  - 750 より上（仮置きの仕様）：x ハイト 420・580 とも 800 → 800、1000 → 1000
  - 大文字・数字の骨格は変わらない
- `expand`（FR-020）：
  - 水平の線（太さ 120、横線 40）→ 太さ 40、垂直の線 → 120、45° の線 → 40＋80×sin45°
  - 円（太さ 120、横線 40）→ 外側と内側の 2 つの輪郭。天辺と底の厚みが 40、左右の端の厚みが 120（それぞれ折れ線の分割による誤差の範囲で）
  - 太さ＝横線の太さのときは向きによらず同じ太さ
  - 輪郭の向き：向きが逆になるように作った 2 つの重なった正方形を合成の前に揃えると、打ち消し合わずに 1 つの輪郭（面積 17,500）になる
- `terminals`：
  - 丸い端 → 線の端にその点の太さの半分の半径の円。垂直な線（太さ 120・横線 40）の端 → 半径 60、水平な線の端 → 半径 20
  - スラブ → 直線の端だけに付き、曲線の終わりと線どうしがつながる端点には付かない
  - スラブの張り出しの上限：左右それぞれに渡した空きの幅を超えない（`capPolys` の引数）。左に空きがない（隣の線と重なる）ときは左へ張り出さない
  - スラブの寸法：太さ 20 → 厚み 12・張り出し 28、太さ 26 → 厚み 12（26×0.45＝11.7 < 12）、太さ 27 → 厚み 12.15、太さ 100 → 厚み 45・張り出し 140
  - 丸い角 → つながる端点にだけ円
  - 尖った角 → つながる端点に miter の多角形。A の頂点の輪郭の上端が、2 本の線の外側の辺を延長した交点の y と一致する（切れ込みがない）
  - miter と bevel の境目：延長がちょうど太さの 4 倍になる角度 → miter、それより少し鋭い角度（延長が 4 倍を超える）→ bevel
  - 平らな端 → 何も足さない
- `union`：
  - 重なった正方形 2 つ → 1 つの輪郭。外側と穴のある図形（O）→ 穴が残る。合成の前後で渡した配列が変わらない
  - 失敗するクリッパーを渡したとき・例外を投げるクリッパーを渡したとき → `{ ok: false, reason: 合成に失敗 }`
- `buildGlyph`：
  - 62 字すべてが既定値で `ok: true` になる。各輪郭のリングがすべて 3 点以上・面積が 0 でない・同じ点が続かない（閉じた多角形として扱える）
  - 62 字すべての穴の数が想定どおり
  - 文字幅 ＝ 輪郭の幅＋余白×2、輪郭の左端 ＝ 余白
  - `bounds` が輪郭の x・y の最小・最大と一致する
  - 返す座標が 1000 単位（10 倍のまま返していない）で、すべて 10 倍すると整数になる（小数第 1 位まで）
  - 傾き 12° で y 座標は変わらず、x だけずれる
  - 幅 1.25 で H → 縦線の太さは既定と同じ（90）のまま、2 本の縦線の中心の間隔が既定の 1.25 倍
  - x ハイトを変えると小文字の高さが変わり、大文字・数字は変わらない（FR-019）
  - 差し替えた骨格を渡すとそれが使われ、太さなどのパラメータも効く（FR-011）。差し替えた小文字の骨格にも x ハイトの伸び縮みが効く
  - 不正な骨格（`validateSkeleton` のテストと同じ例）→ `{ ok: false, reason: 骨格データが不正 }`。例外は投げない
  - 空の結果を返すクリッパーを渡す → スペース以外の文字は `{ ok: false, reason: 輪郭が空 }`、スペースは `ok: true` のまま
  - 範囲外のパラメータを渡すと、上限・下限に丸めた値で組み立てる
  - スペース → `ok: true`、輪郭が空、文字幅 ＝ スペースの幅
  - スラブ：既定の a の右の縦線の足は、右だけに張り出し、左（丸の側）へは張り出さない。H の 2 本の足のスラブは太さの上限 150 でもくっつかない
- `buildGlyphs`：
  - 62 字＋スペースの 63 文字を返し、1 文字が失敗しても他の文字は組み立てられる
  - 全文字に同じ値が効く（FR-007、ストーリー2 シナリオ1）：太さ 150・横線の太さ 150 のとき、I・l・1 の縦線の太さがどれも 150。既定値（90）のときはどれも 90（許容誤差つき）
- 上限・下限の組み合わせ：数値 5 つの上限・下限の 32 通り × 端と角の 6 通り × 62 字がすべて `ok: true` で、穴の数が想定どおり。どの組み合わせでもリングがすべて 3 点以上・面積が 0 でない（閉じた輪郭になる。docs/rules/testing.md）
- 既定の骨格データの検査：キーがちょうど A-Z・a-z・0-9 の 62 個で、すべて `validateSkeleton` に合格する
- 逆コントラスト（2026-11-23 作者が「許す」と決定）：太さ 40・横線の太さ 150 で `buildGlyphs` → H の横棒の厚みが 150、縦線が 40 で、62 字すべて `ok: true`
- 速さ（非機能・性能。根拠は SC-001 と ADR-0001 の V-16。FR-006 の画面での確認は「A の変形画面」の機能で行う）：既定値で A 1 文字の組み立てが 200 回の中央値で 16ms 未満、62 字をまとめた組み立てが 250ms 未満。ADR-0001 の V-16（ブラウザで 95 字 16ms 以下）より緩いのは、コントラストで膨らませの計算が増えるのと、テスト環境のぶれを見込むため

E2E：
- なし（E2E は書かない方針。docs/rules/testing.md）
- 確認用ページは、開発サーバーをブラウザのプレビューで開き、62 字が表示されること・コンソールにエラーがないこと・外部へのリクエストがないことを確かめる（手動）
