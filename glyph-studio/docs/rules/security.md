# セキュリティルール

プランレビュー・実装レビューの判定基準。

- 入力：すべての外部入力（フォーム、クエリ、ファイル、外部APIの応答）を検証する。型・長さ・形式・サイズ上限
- 認証・認可：すべてのエンドポイントで認可を確認する。他人のリソースIDを指定されても見えない・変更できないこと
- シークレット：APIキー・トークンは環境変数で管理し、ログ・エラーメッセージ・クライアントに出さない
- 出力：HTMLへの埋め込みはエスケープする。SQLはパラメータ化する（ORM経由を基本とする）
- ファイル：アップロードは拡張子ではなく中身で種別を判定し、サイズ上限を設ける
- 個人情報：収集は最小限。ログに個人情報を出さない
- 依存：新しいパッケージを追加するときは、プランに理由を書く
- LLMを使う場合：ユーザー入力をプロンプトに入れるときはプロンプトインジェクションを想定し、LLMの出力をそのまま権限のある操作に使わない

## glyph-studio 固有
- 個人情報は扱わない。編集データはブラウザの中だけに保存し、外部へ送信しない
- 保存データを読み込むときは、形を検証してから使う（壊れたデータで画面が落ちないようにする）
