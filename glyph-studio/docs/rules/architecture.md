# アーキテクチャルール

プランレビュー・実装レビュー・リファクタリングの判定基準。プロジェクトに合わせて育てる。

## 構成
- 機能単位でまとめる：`src/features/<機能名>/`
- 1ファイル1責務。300行を超えたら分割を検討する
- 層の向き：UI → ハンドラ／コントローラ → サービス → リポジトリ。逆向きの依存を作らない
- 外部サービスの呼び出しはサービス層の専用モジュールに閉じ込め、テストでモックできるようにする

## 実装
- 既存の仕組み（認可、バリデーション、エラーハンドリング）を流用し、機能専用の仕組みを新設しない
- 純粋関数にできるロジック（変換・正規化・計算）は副作用から切り離す
- 同じ処理が3箇所に現れたら集約する
- 設定値・シークレットは環境変数から読む。コードに直書きしない

## データ
- スキーマ変更はマイグレーションで行う。手でDBを変更しない
- 外部から来た値は境界で検証・正規化してから内部に渡す

## glyph-studio 固有
- 輪郭生成・パラメータ波及・カーニング計算・OTF 書き出しは React に依存しない純粋な関数として `src/features/*/` の中に置き、UI からはそれを呼ぶだけにする
- 輪郭は骨格とパラメータから都度組み立てる。組み立てた輪郭を保存データに入れない
- 座標は 1 em = 1000 単位で持つ。画面の拡大縮小は描画時の変換だけで行う
