# テストルール

テスト網羅レビュー・実装レビューの判定基準。

- 要件定義の受け入れシナリオ1つにつき、最低1つのテストを対応させる
- 境界値は両側を書く（上限ちょうど／上限+1、0件／1件）
- 異常系を書く：空、不正形式、上限超過、外部サービスの失敗
- 先に失敗（Red）を確認してから実装する。最初から通るテストは疑う
- 外部サービスはモックする。単体テストからネットワークに出ない
- スコープ外の振る舞いをテストしない
- テスト名は「〜のとき〜となる」の形で、何を保証するかを読めるようにする

## glyph-studio 固有
- テストは Vitest の単体テストのみ。E2E は書かない（画面はブラウザのプレビューで確認する）
- 輪郭生成は、代表の文字（A、O、g、8、@ など）について「閉じた輪郭になる」「パラメータの上限・下限で穴が潰れない」を確かめる
- OTF 書き出しは、書き出したバイト列を opentype.js で読み戻して、95 文字の cmap・advance width・カーニングを確かめる（SC-003）
