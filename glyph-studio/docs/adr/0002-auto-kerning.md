# ADR-0002：自動カーニングの計算方式と対象の組

状態：調査中 ｜ 起票：2026-11-19 ｜ 決定：— ｜ 決定者：—
関連：docs/requirements/requirements.md の FR-013、FR-014、FR-015、未確定事項 #2、ADR-0001

## 1. 問い
パラメータや骨格が変わるたびに、文字の組の詰め量を形から自動で計算する方式と、どの組を対象にするかを決める。計算方式は輪郭の持ち方（ADR-0001）に依存し、OTF の kern／GPOS の書き出しにも響くため、ストーリー4の実装前に決める。

前提・制約：
- 自動で詰め、気になる組だけ手で直す。手で直した値は自動計算より優先される（作者の回答 E-2、FR-014）
- 対象の文字は ASCII の 95 文字（作者の回答 E-1）
- ブラウザ内だけで動く

判定基準：
- AV・To・LY・Wa など、よく問題になる組で目で見て自然に詰まる
- パラメータを変えたあとの再計算が 1 秒以内（非機能・性能、仮置き）
- opentype.js で書き出せ、macOS・Figma で効く（SC-002、SC-003）

## 2. 選択肢

| #   | 選択肢 | 概要 | 出どころ | 見立て |
| --- | ------ | ---- | -------- | ------ |
| A   | 輪郭の水平距離で計算 | 2 文字を並べたとき、高さごとの左右の輪郭の距離を測り、目標の距離に近づける（光学的な余白の近似） | AI（Claude Opus 5.5） | 検討中 |
| B   | 定番の組の一覧＋簡易計算 | 対象の組を定番の一覧（数百組）に絞り、A の方式で計算する | AI（Claude Opus 5.5） | 検討中 |
| C   | 全組み合わせ（95×95） | 対象を絞らずすべての組を計算し、閾値以下の値は捨てる | AI（Claude Opus 5.5） | 検討中 |
