# 要件定義：glyph-studio

状態：ドラフト｜作成日：2026-11-19｜最終確認者：作者

## 1. 概要
グリッドの上で大文字 A をハンドルで変形すると、その変形から取り出したパラメータが英数字と ASCII 記号の全 95 文字（A-Z、a-z、0-9、記号 32、スペース）に波及し、統一感のあるフォントができる。気になる文字は骨格の点を動かして個別に直し、カーニングを整えて OTF として書き出す。ブラウザだけで動く。

## 2. 背景・課題
- 対象ユーザー：作者自身（フォントの仕組みを学びながら試作する）
- 現状：Glyphs などの専用ツールは、1文字ずつ輪郭を描く必要があり、95 文字を揃えるまでの手間が大きい
- 課題：1文字（A）の変形だけで全体の書体の方向性を決め、短時間で「使えるフォントファイル」まで到達したい

## 3. ユーザーとロール
| ロール | 説明 | できること |
|---|---|---|
| 作者 | 唯一の利用者。ログインなし | すべての操作 |

## 4. ユーザーストーリー
優先度：P1＝MVPに必須／P2＝早期に欲しい／P3＝将来

### ストーリー1：グリッド上で A を変形して書体を決める（P1）
作者として、全体の書体の方向性を1か所で決めるために、グリッドの上で大文字 A のハンドルをドラッグして変形したい。

**なぜこの優先度か**：このアプリの核。A の変形が全文字のもとになる。

**受け入れシナリオ**
1. **Given** 初めて開いた状態、**When** 画面を開く、**Then** グリッドの上に既定の骨格字形から組み立てた A と、各パラメータに対応するハンドルが表示される
2. **Given** 吸着が ON・グリッド 25 単位、**When** 縦線の太さのハンドルをドラッグする、**Then** ハンドルは 25 単位刻みで動き、A の輪郭がドラッグ中に追従して変わる
3. **Given** 太さのハンドルを上限まで動かした、**When** さらに外へドラッグする、**Then** ハンドルは上限で止まり、それ以上太くならない
4. **Given** グリッドを 50 単位にしている、**When** 10 単位に切り替える、**Then** 背景のグリッドの線の間隔が変わり、以後の吸着も 10 単位になる

### ストーリー2：A の変形を全 95 文字に波及させて一覧で見る（P1）
作者として、A で決めた書体が他の文字でどう見えるかを確かめるために、全文字の一覧と試し書きを見たい。

**なぜこの優先度か**：「A をもとに全文字がデザインされる」がこのアプリの価値そのもの。

**受け入れシナリオ**
1. **Given** A の太さを変えた、**When** 一覧を見る、**Then** A-Z、a-z、0-9、ASCII 記号のすべてが同じ太さで表示されている
2. **Given** 一覧を表示している、**When** 試し書き欄に「Hello 2026!」と入力する、**Then** 作成中のフォントでその文字列が表示される
3. **Given** 一覧を表示している、**When** g をクリックする、**Then** g の個別編集画面に移る

### ストーリー3：文字ごとに骨格の点を動かして直す（P1）
作者として、自動で作られた形が気に入らない文字を直すために、その文字の骨格の点をグリッド上で動かしたい。

**なぜこの優先度か**：パラメータだけでは全文字が満足な形にならないため、個別に直す手段が必須。

**受け入れシナリオ**
1. **Given** g の個別編集画面、**When** 骨格の点をドラッグする、**Then** 点はグリッドに吸着して動き、太さ・丸みなどは全体のパラメータのまま輪郭が組み直される
2. **Given** g の骨格を直した、**When** A に戻って太さを変える、**Then** g は直した骨格のまま、新しい太さで表示される
3. **Given** g の骨格を直した、**When** 一覧を見る、**Then** g が個別に直した文字だとわかる印が付いている

### ストーリー4：カーニングを整える（P1）
作者として、文字を並べたときの間隔を自然にするために、カーニングを自動で詰め、気になる組だけ手で直したい。

**なぜこの優先度か**：作者が MVP に必須と判断した（インタビュー D-1）。

**受け入れシナリオ**
1. **Given** 書体を変形した、**When** カーニング画面を開く、**Then** 対象の組（AV、To、LY など）に、形から自動で計算した詰め量が入っている
2. **Given** カーニング画面で AV を選んだ、**When** 詰め量を変える、**Then** プレビューの AV の間隔が変わり、その組は手で直した値として自動計算より優先される
3. **Given** AV を手で直した、**When** A の幅を変える、**Then** 手で直した AV の値は変わらず、他の自動の組は計算し直される

### ストーリー5：OTF として書き出す（P1）
作者として、作ったフォントを Mac/Windows や Figma で使うために、OTF ファイルとしてダウンロードしたい。

**なぜこの優先度か**：最終成果物。これがないと作ったものを使えない。

**受け入れシナリオ**
1. **Given** フォント名に「MyGlyph」と入力した、**When** ダウンロードを押す、**Then** `MyGlyph.otf` がダウンロードされ、95 文字とカーニングを含む
2. **Given** フォント名が空、**When** ダウンロードを押す、**Then** ダウンロードされず、名前の入力を求める表示が出る
3. **Given** ダウンロードした OTF、**When** Mac にインストールして Figma で入力する、**Then** 画面と同じ形で表示される

### ストーリー6：編集途中のデータを自動で残す（P1）
作者として、作業を中断しても続きから再開するために、編集内容をブラウザに自動保存したい。

**なぜこの優先度か**：95 文字を整えるには複数回の作業が前提になるため。

**受け入れシナリオ**
1. **Given** A を変形し g を直した、**When** ページをリロードする、**Then** 変形したパラメータ、g の骨格、カーニング、フォント名、グリッド設定が復元される
2. **Given** 保存データが壊れている（読み込めない）、**When** ページを開く、**Then** 既定の状態で開き、復元できなかったことを表示する

### ストーリー7：アクセント付き文字（P2）
作者として、é ü ñ などを使うために、ベース文字とアクセント記号を重ねた文字を作りたい。

### ストーリー8：複数ウェイト・可変フォント（P2）
作者として、Regular と Bold を揃えて使うために、複数のウェイトや可変フォントを書き出したい。

## 5. 機能要件

| ID | 要件 | ストーリー |
|---|---|---|
| FR-001 | 初回表示のとき、既定の骨格字形と既定パラメータから組み立てた A が、グリッドの上に 1000 単位（UPM 1000）の座標で表示される | 1 |
| FR-002 | A の上には各パラメータに対応するハンドルが表示され、ハンドルをドラッグするとそのパラメータの値が変わる。パラメータは 7 つ：太さ（縦線の太さ）、横線の太さ、幅、傾き、x ハイト、端の形（平ら／丸／スラブ。スラブは直線の端だけに付く）、角の丸み（尖り／丸）。x ハイトなど A の形では表せないパラメータをどう操作するかは【要確認】 | 1 |
| FR-003 | 吸着が ON のとき、ハンドルと骨格の点はグリッドの間隔の倍数の位置にだけ置かれる。OFF のときは 1 単位で置かれる | 1, 3 |
| FR-004 | グリッドの間隔を 10／25／50 単位から選んだとき、背景の線の間隔と吸着の間隔がその値になる | 1 |
| FR-005 | ハンドルをパラメータの上限・下限を超える位置へドラッグしたとき、値は上限・下限で止まる。上限・下限の値は【要確認】 | 1 |
| FR-006 | ハンドルのドラッグ中、A の輪郭はドラッグに追従して組み直される | 1 |
| FR-007 | パラメータが変わったとき、95 文字すべての輪郭が同じパラメータで組み直される | 2 |
| FR-008 | 一覧画面には 95 文字が表示され、文字をクリックするとその文字の個別編集画面に移る | 2 |
| FR-009 | 試し書き欄に入力した文字列は、作成中のフォント（カーニングを含む）で表示される。対象外の文字は空白として扱う | 2 |
| FR-010 | 個別編集画面で骨格の点をドラッグしたとき、その文字の骨格だけが変わり、輪郭は全体のパラメータで組み直される | 3 |
| FR-011 | 骨格を個別に直した文字は、そのあとパラメータが変わっても直した骨格を保ち、新しいパラメータで組み直される | 3 |
| FR-012 | 骨格を個別に直した文字は、一覧で区別できる印が付く | 3 |
| FR-013 | パラメータまたは骨格が変わったとき、対象の組のカーニング値が形から自動で計算し直される。対象の組と計算方式は ADR-0002 | 4 |
| FR-014 | カーニングの組を手で直したとき、その値は自動計算より優先され、以後の自動計算で上書きされない | 4 |
| FR-015 | ダウンロードを押したとき、入力したフォント名をファイル名とファミリー名にした OTF が生成され、95 文字（.notdef を除く）、各文字の advance width、カーニングを含む | 5 |
| FR-016 | フォント名が空のままダウンロードを押したとき、ファイルは生成されず、名前の入力を求める表示が出る | 5 |
| FR-017 | 編集内容（パラメータ、個別に直した骨格、手で直したカーニング、フォント名、グリッド設定）は変更のたびにブラウザに自動保存され、リロード後に復元される | 6 |
| FR-018 | 保存データを読み込めないとき、既定の状態で開き、復元できなかったことを表示する | 6 |
| FR-019 | x ハイトを変えたとき、小文字はベースラインから x ハイトまでの間だけが伸び縮みし、アセンダー・ディセンダー側の部分と、大文字・数字の形は変わらない | 1, 2 |
| FR-020 | 横線の太さを変えたとき、線の太さは向きに応じて変わる：水平な線は横線の太さ、垂直な線は太さになり、斜めの線や曲線はその間で連続的に変わる | 1, 2 |

## 6. エッジケース・異常系
- パラメータを上限・下限まで振っても、e・8・B などの穴が潰れない範囲に上限・下限を決める（FR-005）
- 個別に直した骨格と極端なパラメータの組み合わせで輪郭が重なる・破綻する場合の扱い【要確認】
- 試し書きに日本語や対象外の文字を入れた場合は空白として扱う（FR-009）
- フォント名に OTF の名前テーブルで使えない文字（全角・記号）が入った場合の扱い【要確認】
- localStorage の容量超過で保存に失敗した場合の扱い【要確認】

## 7. 非機能要件
| 区分 | 要件 |
|---|---|
| 性能 | ハンドルのドラッグ中、A の輪郭がもたつかずに追従する。一覧の 95 文字はドラッグを離してから 1 秒以内に更新される（仮置き） |
| セキュリティ | 個人情報は扱わない。データはブラウザの中だけにあり、外部へ送信しない |
| コスト | 外部 API・サーバーを使わないため 0 円 |
| 対応環境 | デスクトップの最新 Chrome（仮置き）。ローカルの `npm run dev` で動かす |

## 8. データ（主要エンティティ）
| エンティティ | 主な属性 | 関連 |
|---|---|---|
| フォントプロジェクト | フォント名、グリッド間隔、吸着 ON/OFF | パラメータ 1、字形 95、カーニングの組 n |
| パラメータ | 太さ、横線の太さ、幅、傾き、x ハイト、端の形（平ら／丸／スラブ）、角の丸み（尖り／丸） | フォントプロジェクトに 1 つ |
| 字形 | 文字（Unicode）、骨格（既定 or 個別に直したもの）、個別に直したかどうか、左右の余白 | 輪郭は骨格とパラメータから都度組み立てる（保存しない） |
| カーニングの組 | 左の文字、右の文字、値、手で直したかどうか | 字形 2 つ |

## 11. スコープ外
v1では扱わないもの。AIが「ついでに」作らないための明記。
- 日本語（かな・漢字）
- アクセント付き文字（P2：ストーリー7）
- 複数ウェイト・可変フォント（P2：ストーリー8）
- TTF・WOFF2・作業データ（JSON）の書き出し
- 作者名・ライセンスなどフォント名以外のメタ情報の入力
- 輪郭の点を直接編集すること（編集できるのは骨格の点とパラメータだけ）
- A 以外の文字で全体のパラメータを変えること
- ログイン・サーバーへの保存・複数端末での同期・公開ホスティング
- AI による字形の生成
- E2E テスト
