# glyph-studio

ここは `uchu-jin/poc` モノレポの中の1つの POC。**ファイルはすべて `glyph-studio/` の中に作り、リポジトリ直下（`../`）には何も置かない。**

グリッドの上で大文字 A をハンドルで変形すると、その変形から取り出したパラメータ（太さ・傾き・幅・角の丸み・端の形など）が英数字と ASCII 記号の全 95 文字に波及し、OTF として書き出せる Web アプリ。作者自身がフォントの仕組みを学びながら試作するための POC。
要件定義: docs/requirements/requirements.md

## 技術スタック
- TypeScript / React / Vite。処理はすべてブラウザ内で完結し、サーバーは持たない（ローカルの `npm run dev` で動かす）
- 字形の描画：SVG
- OTF の書き出し：opentype.js
- 輪郭の合成：clipper-lib（ADR-0001）
- 編集データの保存：ブラウザ（localStorage／IndexedDB）
- テスト：Vitest（単体のみ。E2E は書かない）
- Lint/Format：ESLint + Prettier（signal-upload に合わせる）
- 外部 API・LLM は使わない

## フォントの作り方（全機能に共通する前提）
- 字形は「骨格（中心線）＋グローバルパラメータ」から輪郭を組み立てる。輪郭を直接編集するのではない
- 座標は 1 em = 1000 単位（UPM 1000）。画面のグリッドは 10/25/50 単位を切り替える
- パラメータは A の上のハンドルで決め、全文字に同じ値が届く。文字ごとに変えられるのは骨格の点だけ
- 個別に直した骨格は、そのあとパラメータが変わっても残る
- ハンドルには上限・下限があり、形が破綻する値にはできない
- 骨格からの輪郭生成は ADR-0001（採択）：骨格の各線を自前のコードで膨らませ、端・角の図形を足し、clipper-lib で 1 つの輪郭にまとめる（座標 10 倍の整数、NonZero）
- 自動カーニングの方式は ADR-0002（調査中。採択までそれに基づいて実装しない）

## よく使うコマンド
- 開発サーバー：`npm run dev`
- 単体テスト：`npm test -- --run`
- Lint：`npm run lint`
- 型チェック：`npm run typecheck`

## ディレクトリ
- src/features/<機能名>/ ：機能単位のコード
- docs/requirements/ ：要件定義（FR-xxx / SC-xxx で参照する）
- docs/rules/ ：判定基準となるルール（architecture / security / testing）
- docs/workflow.md ：開発手順と機能ごとの進み具合
- docs/adr/ ：設計判断の記録（ADR-NNNN で参照する。書き方は docs/adr/README.md）
- .claude/plans/ ：機能ごとのプラン（_template.md を複製して使う）

## 開発の進め方
- 開発手順（8段階）と機能ごとの進み具合：docs/workflow.md。各コマンドの終わりに、その機能の行を更新する。段階を飛ばすときは理由を「メモ」に書く
- 実装に入る前に、必ず .claude/plans/ にプランを作る（/plan）
- プランは8項目で書く：概要／背景／詳細設計／テスト影響範囲／新規テストケース／実装順／コミット前テスト実行／スコープ外
- 未確定の論点は【要確認】を付けて残し、推測で埋めない
- 実装順には、タスクごとの担当モデル・サブエージェントを書く（単純作業は安価なモデル、中核ロジックは上位モデル）

## 設計判断のルール（ADR）
- 選択肢が2つ以上あり後から変えにくい判断は、調査を始めた時点で docs/adr/ に起票する（/adr、状態：調査中）
- AIの提案は、検証するまで事実として扱わない。提案と検証結果（コマンド・出力・一次資料）を ADR の検証ログに追記する。過去のエントリは書き換えない
- 選ばなかった選択肢は、理由と再検討する条件を ADR に残す
- 「採択」「却下」「置換」にするのは人間だけ。採択されていない ADR に基づいて実装しない
- ADR の決定を実装した箇所には、コメントで `ADR-NNNN` と書き、ADR の「実装箇所」にも足す

## 実装のルール
- プランの実装順に従う
- プランにない変更が必要になったら、実装せず立ち止まって報告する
- 要件定義・プランの「スコープ外」に書かれたものは作らない
- 輪郭生成・パラメータ波及・カーニング計算・OTF 書き出しは React に依存しない純粋な関数にし、単体テストできるようにする

## テストのルール
- 先に失敗するテストを書き、失敗（Red）を確認してから実装する
- 最初から通ったテストは、実装済みかassertが弱いかを報告する
- 完了報告には、実行コマンドと出力を付ける
- OTF 書き出しは、書き出したバイト列を opentype.js で読み戻して、文字数・cmap・advance width・カーニングを確かめる
- コミット前に実行：単体テスト全件、型チェック、Lint

## レビューのルール
- 指摘は P0（実装前に必ず直す）／P1（推奨）／P2（軽微）で分類する
- 指摘には「どの記述が・どの基準と・なぜずれるか」を添える
- 判定基準：docs/rules/、docs/requirements/

## 報告のルール
- 根拠を確認できないものは推測で埋めず「不明」と答える
- プランに書いていない判断は「実装時の判断」と明示する

## 触らない場所
- リポジトリ直下（`../`）と他の POC のフォルダ
- `.env*`、`package-lock.json` の手編集、`dist/` などの自動生成ファイル
