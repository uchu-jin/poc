## 1. プロダクト定義

### 1.1 プロダクト名
みちすがら（ロケーション型 AI 旅コンパニオン）

### 1.2 目的
観光地を散歩しているユーザーに、その場所の周辺情報（観光地、天気）と AI との会話を届け、観光地を効率よく、楽しく発見・理解できるようにする。

### 1.3 コア価値提案
- **位置情報のリアルタイム取得**：ユーザーの現在地を自動的に把握する
- **周辺情報の自動検出**：近くの観光地や食事スポットを自動で取得する
- **AI との自然な対話**：位置情報と周辺情報を踏まえた会話を通じて、地元の魅力を発見してもらう

---

## 2. ターゲットユーザー

### 2.1 ユーザーペルソナ
- **年代**：20 代〜40 代
- **背景**：観光地を訪れている、または初めての土地を探索している
- **ニーズ**：
  - 周辺の観光スポットを効率よく知りたい
  - スマホ 1 台で情報を得たい
  - ガイドブックより自然な情報がほしい

### 2.2 使用シーン
1. 観光地を散歩しているとき
2. 初めての街で周辺情報を知りたいとき
3. AI との会話を通じて新しい発見をしたいとき

### 2.3 使用デバイス
- **主体**：スマートフォン
- **環境**：屋外、GPS を受信できる環境

## 3. 機能要件

### 3.1 MVP（最小限の実装）

#### F-1：位置情報の取得と表示
- ブラウザの Geolocation API を使う
- 初回起動時に GPS の許可を求める
- 現在地を「緯度, 経度」で表示する。手入力で決めた位置のときは市区町村名を表示する 〔v1.1〕D-19
- 1 分ごとに位置情報を自動で更新する。タブが前面に戻ったときにもすぐ取得する 〔v1.1〕D-11
- 位置の更新に失敗した場合は、前回の位置を使い続ける
- 精度が 100m より悪い測位は捨てる。ただし、まだ位置がない最初の 1 回は採用する 〔v1.1〕D-11
- **周辺情報を最後に取得した地点から 300m 以上**移動したら「📍 場所が変わりました」と通知し、周辺情報を取り直す 〔v1.1〕D-11
- 取得中・成功・失敗・手入力のステータスを表示する。色だけでなく文言でも区別する

#### F-2：観光地情報の取得
- Overpass API を**ブラウザから直接**呼ぶ。失敗したらミラーサーバーに切り替える 〔v1.1〕D-09
- カテゴリ：**寺社（仏教寺院と神社）**、博物館、展望台、レストラン。名前のない POI は除外する 〔v1.1〕D-10
- 距離：1km 以内。0 件なら 5km に広げる（AC-2）
- **AI に渡す件数と表示件数：カテゴリごとに近い順で最大 5 件、合計 20 件まで** 〔v1.1〕D-07
- 画面では、ヘッダー下の折りたたみ式チップ（「周辺 12 件 ▼」）に一覧を出す。項目をタップすると「〇〇について教えて」が入力欄に入る 〔v1.1〕D-07
- 再取得するのは F-1 の移動判定で移動とみなしたときだけ。同じ地点は 10 分以内に再検索しない 〔v1.1〕D-11
- 応答を待つのは最大 4 秒。それを過ぎたら周辺情報なしで先に進み、届いた時点で反映して「周辺情報が届きました」と通知する 〔v1.1〕D-09

#### F-3：天気情報の取得
- Open-Meteo API を使う
- 取得するデータ：気温、天候コード（日本語ラベルに変換）、相対湿度
- 観光地情報と並行して取得する。15 分間キャッシュする 〔v1.1〕D-11

#### F-4：AI との会話
- Claude API を使う。**既定のモデルは `claude-haiku-5-5`、環境変数で `claude-sonnet-5-5` に切り替えられる** 〔v1.1〕D-08
- 返答は**ストリーミングで表示**する（文字が順に出る） 〔v1.1〕D-08
- AI の役割：旅のコンパニオン。観光地に詳しい
- 入力：ユーザーのテキスト
- コンテキスト：現在地、周辺の観光地（F-2 の上限内）、天気、チャット履歴の**直近 20 件** 〔v1.1〕D-14
- コンテキストの形式：自然言語のテキスト（構造化フォーマットではない）。文章への組み立てはサーバー側で行う
- **AI への指示（システムプロンプト）はサーバー側で固定する。クライアントからは受け付けない** 〔v1.1〕D-21
- 出力：自然な日本語のテキスト（1 回のメッセージ）。目安は 200〜400 字
- 初回メッセージ：位置と天気が揃ったら、AI が自動で生成する（観光地は最大 4 秒まで待つ）
  - 再起動時は、次のいずれかに当てはまるときだけ生成する：履歴がない、前回の挨拶から 6 時間以上経った、前回の位置から 300m 以上離れた 〔v1.1〕D-13
- 位置が移動したとき：新しい位置の周辺情報を取得してコンテキストに反映し、「場所が変わりました」と通知する。**AI は自分からは話しかけない**。通知に「この辺りを教えて」ボタンを置く 〔v1.1〕D-12
- AI の確実性：渡された観光地以外の施設に触れるのは、実在が確実な場合に限る。営業時間や料金は断定しない。AI による提案には「AI による提案です。最新情報は現地でご確認ください」と注記する 〔v1.1〕D-15

#### F-5：チャット UI
- 画面構成：メッセージ表示エリア（スクロール対応）＋入力フォーム
- メッセージの表示：ユーザーは右側に紫色で、AI は左側に白色で表示して区別する。システム通知は中央に小さく表示する 〔v1.1〕
- タイムスタンプ：各メッセージに ISO 8601 形式の時刻を付けて保存する。表示は HH:MM
- 入力フォーム：テキスト入力と送信ボタン
- キーボード操作 〔v1.1〕D-22
  - PC：Enter で送信、Shift＋Enter で改行
  - タッチ端末：Enter で改行、送信はボタンのみ
  - **日本語変換中（IME 変換中）の Enter では送信しない**
- 「履歴をすべて消去」メニューを用意する（確認ダイアログあり） 〔v1.1〕D-23

#### F-6：データの永続化
- localStorage に保存するもの：チャット履歴（最大 100 件。超えたら古いものから削除）、最後の位置情報、**送信待ちキュー** 〔v1.1〕D-05
- 保存のタイミング：メッセージを追加したとき、位置情報を更新したとき
- 復元：アプリ起動時に localStorage から読み込む
- 保存に失敗したとき（容量超過、データ破損、localStorage が使えない環境）でもアプリは動き続ける 〔v1.1〕

#### F-7：エラーハンドリング

| エラーの状況 | 対応 |
|---|---|
| GPS の許可がない | **地方 → 都道府県 → 市区町村のボタン選択**を表示する（東京駅が初期選択）。「GPS を再試行」ボタンも出す 〔v1.1〕D-06, D-17 |
| GPS の取得に失敗 | エラーを表示する。前回の位置があればそれを使い、なければ住所選択を表示する |
| 手入力の後に GPS が成功 | 自動で GPS に切り替え、通知する 〔v1.1〕D-18 |
| Overpass API が失敗 | AI が「観光地情報が取得できません」と説明し、会話は続けられる。5km 検索には進まない 〔v1.1〕 |
| Open-Meteo API が失敗 | 天気情報なしで会話を続ける |
| Claude API が失敗 | 「接続エラーが発生しました。もう一度送信してください」と表示する |
| Claude API のレート制限 | 「リクエストが多いです。少し待ってから試してください」と表示する |
| AI が回答を拒否 | 「その話題にはお答えできません。別の質問をどうぞ」と表示する 〔v1.1〕 |
| ストリームの途中で切断 | 受信できた部分を残し、「再送」ボタンを出す 〔v1.1〕 |
| ネット接続が切れた | 履歴は表示したまま、**送信は受け付けて「送信待ち」としてキューに積む**。復帰したら、たまった発話を**1 リクエストにまとめて**自動送信する 〔v1.1〕D-05 |

## 4. 非機能要件

### 4.1 パフォーマンス
- **初回起動から会話できるまで**：5 秒以内。Overpass の応答が 4 秒を超えた場合は、観光地情報なしで先に挨拶して満たす 〔v1.1〕D-09
- **AI の応答時間**：最初の文字が出るまで 3 秒以内、通常の回答が出終わるまで 5 秒以内 〔v1.1〕D-08
- **位置情報の更新間隔**：1 分ごと

### 4.2 対応デバイス・ブラウザ
- **デバイス**：iOS、Android のスマートフォン（推奨）
- **ブラウザ**：Chrome、Safari、Firefox（最新 2 バージョン）
- **必須の機能**：Geolocation API、localStorage、HTTPS（GPS の取得に必須）

### 4.3 ストレージ
- **localStorage の使用量**：1MB 未満（チャット履歴 100 件を想定）
- **API のキャッシュ**：メモリ上に置く（観光地情報、天気情報）

### 4.4 セキュリティ・プライバシー 〔v1.1〕D-04, D-21
- **API キーの管理**：Claude API キーはサーバー側の関数（Cloudflare Pages Functions）だけが持つ。クライアントには出さない
- **通信**：HTTPS のみ
- **位置情報**
  - 自前のサーバー（`/api/chat`）と Open-Meteo には、**小数 3 桁（約 100m）に丸めた座標**だけを送る
  - Overpass には、丸めた座標を中心に半径を 150m 広げて問い合わせる。正確な距離は、端末内の正確な座標で計算し直す
  - サーバーは座標・会話内容を保存せず、ログにも出さない。ログに残すのはステータス、所要時間、トークン数のみ
  - 正確な座標は端末の localStorage にだけ保存する
- **プロキシの悪用対策**：Origin の照合、IP ごとのレート制限（20 回 / 分）、リクエストサイズと項目の上限検証、Anthropic コンソールでの月額上限設定

### 4.5 アクセシビリティ
- **言語**：日本語（MVP）
- **フォントサイズ**：本文は 16px 以上
- **コントラスト**：WCAG AA に準拠

### 4.6 日本の地理データ 〔v1.1〕D-16
- **必須データ**：地方（8 区分）、都道府県、市区町村（政令市は区単位）、代表座標
- **ソース**：公的なオープンデータ（国土数値情報の市町村役場等データを想定。採用前にライセンスを確認する）を変換スクリプトで JSON 化する。手書きや AI による生成はしない
- **使用目的**：GPS が使えないときの住所選択、既定の位置（東京駅 35.6812, 139.7671）
- **代表座標**：市区町村役場の位置
- 出典とライセンスは README と画面のフッターに表記する

## 5. 技術仕様 〔v1.1〕D-20

### 5.1 使用技術
- **言語**：HTML、CSS、TypeScript
- **ビルド**：Vite（フレームワークなし）
- **サーバー側**：Cloudflare Pages Functions（`/api/chat`）。Anthropic TypeScript SDK を使う
- **ストレージ**：localStorage
- **デプロイ**：Cloudflare Pages（ルートディレクトリは `location`）
- **テスト**：Vitest（ユニット、Functions）、Playwright（E2E）

### 5.2 外部 API

| API | 用途 | 呼び出し元 | 認証 | 仕様 |
|---|---|---|---|---|
| Geolocation API | GPS の取得 | ブラウザ | なし（ユーザーの許可が必要） | 緯度、経度、精度 |
| Overpass API | 観光地の取得 | ブラウザ | なし | POST、OverpassQL。ミラーあり |
| Open-Meteo API | 天気の取得 | ブラウザ | なし | GET、JSON |
| Claude API | AI の会話生成 | Pages Functions | API キー（サーバー側のみ） | Messages API、ストリーミング、`claude-haiku-5-5`（切替可） |

## 6. 画面設計（UI 要件）

### 6.1 画面構成
画面はチャット画面の 1 つだけ。

```
┌─────────────────────────┐
│ 🗺️ みちすがら      [≡]  │ ← メニュー（履歴の消去）〔v1.1〕
│ ● 成功 📍 35.6749, 139.7506│
│ ☁ くもり 18℃ 65%        │ 〔v1.1〕
│ [周辺 12件 ▼]           │ 〔v1.1〕
├─────────────────────────┤
│ メッセージエリア          │
│ （スクロール対応）         │
│ [AI メッセージ]           │
│        [ユーザーメッセージ]│
│   ─ 📍 場所が変わりました ─ │ 〔v1.1〕
├─────────────────────────┤
│ [質問やコメントを入力...] [→]│
└─────────────────────────┘
```

### 6.2 各要素の詳細

**ヘッダー**
- アプリ名：「🗺️ みちすがら」
- GPS ステータス：取得中 / 成功 / 失敗 / 手入力
- 位置の表示：「📍 35.6749, 139.7506」（緯度, 経度。表示は小数 4 桁。送信用の 3 桁の丸め D-04 とは別物）、または「📍 東京都渋谷区」（手入力のとき）
- 天気の小さな表示、周辺 POI のチップ 〔v1.1〕

**メッセージエリア**
- スクロールできる。最下部付近を見ているときだけ、新しいメッセージに追従する 〔v1.1〕
- メッセージは吹き出しで表示し、ユーザーと AI で色を分ける
- 時刻は HH:MM 形式で表示する

**入力フォーム**
- プレースホルダー：「質問やコメントを入力...」
- 送信ボタン：「→」アイコン。オフライン中は「送信待ち」と表示する 〔v1.1〕
- キー操作は F-5 のとおり

## 7. 受け入れ基準（Acceptance Criteria）

### AC-1：GPS 取得機能
- [ ] アプリを起動すると、GPS の許可ダイアログが表示される
- [ ] ユーザーが許可すると GPS が取得でき、ステータスが「成功」に変わる
- [ ] 位置情報が「緯度, 経度」で表示される
- [ ] 1 分ごとに位置情報が更新される
- [ ] 300m 未満の移動では通知されず、300m 以上の移動で通知される 〔v1.1〕

### AC-1b：GPS が使えないときの住所選択
- [ ] GPS が失敗すると、住所選択が表示される
- [ ] 「地方を選択」ボタンが表示される（関東、関西、九州など）
- [ ] 地方を選ぶと「都道府県を選択」ボタンが表示される
- [ ] 都道府県を選ぶと「市区町村を選択」ボタンが表示される
- [ ] 市区町村を選ぶと、その代表座標が現在地に設定され、ヘッダーに市区町村名が表示される
- [ ] 初期選択は東京（東京駅）。ユーザーが選ばないうちに東京で会話を始めることはない 〔v1.1〕
- [ ] 手入力の後に GPS が成功すると、GPS に切り替わって通知される 〔v1.1〕

### AC-2：観光地情報の取得
- [ ] GPS の取得後、スピナーを表示して Overpass API を呼ぶ
- [ ] 1km 以内の寺社（寺院・神社）、博物館、展望台、レストランが取得される 〔v1.1〕
- [ ] 1km で 0 件なら、5km の範囲で検索する
- [ ] 5km でも 0 件なら、AI に「おすすめのエリア」を提案させる（観光地が多いエリアの名前と行き方）
- [ ] 1 件以上見つかれば OK（全カテゴリが揃う必要はない）
- [ ] API が失敗したときは、AI がその旨を説明する。5km 検索には進まない 〔v1.1〕
- [ ] AI に渡す件数はカテゴリごとに 5 件以下、合計 20 件以下 〔v1.1〕
- [ ] 4 秒以内に応答がなければ先に挨拶し、後から周辺情報が届いたことを通知する 〔v1.1〕

### AC-3：天気情報の取得
- [ ] Open-Meteo API から気温、湿度、天候が取得される
- [ ] 天気情報が AI のコンテキストに含まれる
- [ ] API が失敗しても、天気情報なしで会話を続けられる

### AC-4：AI との会話
- [ ] 位置、観光地、天気を取得した後、AI が初回メッセージを自動で生成する
- [ ] ユーザーがメッセージを入力すると、AI が位置情報を踏まえて返答する
- [ ] チャット履歴の直近 20 件がコンテキストに含まれる 〔v1.1〕
- [ ] コンテキストは自然言語の形式で AI に渡される
- [ ] 最初の文字は 3 秒以内に表示され、通常の回答は 5 秒以内に出終わる 〔v1.1〕
- [ ] 観光地が 1km 以内で見つからない場合、AI の返答に 5km エリアの提案も含まれる
- [ ] 再起動したとき、F-4 の初回メッセージの条件（D-13）に当てはまらなければ挨拶を再生成しない 〔v1.1〕

### AC-4b：観光地がない場合の処理
- [ ] 1km 範囲で観光地が見つからない場合、スピナーを表示して 5km 範囲で再検索する
- [ ] 5km でも見つからない場合、AI に「近くの観光地が多いエリア」を提案させる
- [ ] AI はおすすめエリアの名前（例：「京都の伏見稲荷周辺」）と行き方を説明する
- [ ] このおすすめは初回メッセージに含まれ、「AI による提案です」の注記が付く 〔v1.1〕

### AC-5：ローディング状態
- [ ] 位置、観光地、天気の取得中にスピナーが表示される
- [ ] 観光地の検索範囲を 1km から 5km に広げるときもスピナーが表示される（文言が変わる）
- [ ] AI がメッセージを生成している間、スピナーが表示される
- [ ] 位置が変わったら、その旨がシステム通知で表示される（「📍 場所が変わりました」）

### AC-6：チャット UI
- [ ] メッセージが時系列で表示される
- [ ] ユーザーのメッセージと AI のメッセージが見た目で区別できる
- [ ] PC では Enter キーで送信できる。日本語変換中の Enter では送信されない 〔v1.1〕
- [ ] 送信すると入力欄が空になり、メッセージエリアが最下部までスクロールする

### AC-7：データの永続化
- [ ] アプリを閉じても、チャット履歴が復元される
- [ ] 位置情報が localStorage に保存される
- [ ] 再起動すると、前回の会話が表示される
- [ ] 送信待ちのメッセージもリロード後に残る 〔v1.1〕

### AC-8：エラーハンドリング
- [ ] GPS が失敗すると通知され、住所選択（地方 → 都道府県 → 市区町村）が表示される
- [ ] API が失敗すると、適切なエラーメッセージが表示される（F-7 の表）
- [ ] オフライン中に送ったメッセージは「送信待ち」になり、ネット接続が戻ると 1 リクエストにまとめて自動送信される 〔v1.1〕
- [ ] 位置の取得に失敗したときは、前回の位置を使い続ける

### AC-9：セキュリティ・プライバシー 〔v1.1〕
- [ ] `/api/chat` に送られる座標は小数 3 桁以下である
- [ ] 許可していない Origin からのリクエストは 403 で拒否される
- [ ] レート制限を超えると 429 になり、F-7 の文言が表示される
- [ ] サーバーのログに座標や会話の本文が出ない
- [ ] クライアントのコードに API キーが含まれない
