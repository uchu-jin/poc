## 1. 概要

Vite＋TypeScript の土台（1ファイル出力・Vitest・Playwright・ESLint）を用意し、Three.js に依存しない `src/core/`（Rng・Clock・Tree の成長・Store）を作る。画面は「種をまく」ボタン、左上の日数・段階・残り時間、`?debug` のときだけ出る簡易な 2D の横姿（canvas）まで。3D は次の機能。
保存データが壊れている・版が違うときは読み込まず、上書きもしない。作者が「退避して新しく始める」を選んだときだけ、元の文字列を別キーに写してから種をまき直す。localStorage に書けないときは警告を出して続ける。

## 2. 背景

- ストーリー1（種まき〜実時間成長）が他のすべての前提。剪定・評価・描画は Tree と保存データの形の上に乗る
- 作者の回答（2026-10-20）：`?speed` は別キーに保存／仮の表示は `?debug` の 2D 横姿／遊ぶときは `dist/index.html` を直接開く／E2E は chromium と firefox
- 作者の回答（2026-10-21、プランレビューを受けて）：葉は枝先の近くだけに付く／壊れた保存データは退避して種から始められる／`?speed` の木は閉じている間は止める／調整用に `__bonsai.plant(seed)` を置く
- これで要件 12章の #4・#5・#12・#13 が決まった。#1・#2 は仮置きの数値で作り、実装順 9 で作者と決め直す。#6 は ADR-0001。#8 はこの機能では「1ファイル出力の方法」だけ決め、Three.js の版と読み込み方は描画のプランで決める
- 葉の付き方と壊れた保存データの扱いは要件の解釈を広げるため、要件定義（FR-044・付録 A.2 ほか）も合わせて直す

- `clock.ts` - `computeTicks(now, lastTickAt, speed)` → `{ steps, lastTickAt }`
  - 経過 × speed を `GROWTH_STEP_MS` で割った整数部だけ進め、`lastTickAt` は `lastTickAt + Math.floor(steps × GROWTH_STEP_MS / speed)` にする（ミリ秒の整数を保つ。端数は次の計算に持ち越す）
  - 経過が負なら `{ steps: 0, lastTickAt: max(now, TIME_FLOOR) }`。`TIME_FLOOR` は 2026-01-01（1,767,225,600,000）。時計が 2026 年より前に戻っても、保存データの検証を外れないようにする
  - `progress(now, lastTickAt, speed)` → 0〜1（描画の補間用。保存しない）
- `types.ts` - `SaveData`・`TreeNode`・`Leaf`・`Wire`・`Traits`（要件 付録 A.5 の形＋ADR-0001 の項目：保存データ直下の `nextId`、節の `boostUntil`・`wire` の中身）
- `tree.ts` - `createTree(seed, now)`（`createdAt`・`lastTickAt` は `max(now, TIME_FLOOR)`）、`step(data)`、`advance(data, n)`、`stageOf(age)`、`growthFactor(water)`。`step` は FR-004 の順で処理する。針金で曲げた形の維持と葉の生え直しは後の機能で中身を足す
- `store.ts` - `parseSave(text)` → `{kind:'ok', data} | {kind:'invalid', reason}`、`load(storage, key)` → `{kind:'empty'} | {kind:'ok', data} | {kind:'invalid', reason, raw}`、`save(storage, key, data)` → `{ok:true} | {ok:false, reason}`、`backupBroken(storage, raw, now)` → 退避したキー名か失敗。`storage` は `getItem/setItem` だけの型で受け取り、テストで差し替える。**以後は zod の parse 結果だけを使い、検証前の生の値を他へ渡さない**

保存データの検証（zod。下の範囲から外れたら invalid）：

| 項目 | 範囲 |
|---|---|
| `version` | 1 |
| `seed`・`rngState` | 0 以上 2³²−1 以下の整数 |
| `createdAt`・`lastTickAt` | 整数。どちらも `TIME_FLOOR`（2026-01-01）以上、8.64×10¹⁵ 以下。**`createdAt` と `lastTickAt` の大小は見ない**（時計が種まきより前に戻ると `lastTickAt < createdAt` になりうるため。テストレビュー P0-2） |
| `age` | 0 以上 10⁹ 以下の整数（実装レビュー P1-①で上限を追加） |
| `water` | 0 以上 100 以下の整数 |
| `traits` の4つ | 0 以上 1 以下 |
| `nextId` | 10⁹ 以下の整数で、どの節の `id` よりも大きい |
| `nodes` | 1 個以上 `SAVE_LIMIT_NODES` 以下。先頭が根元（`parent` −1）で、根元はそれ1つ。`id` は重複なしの小さい順。`parent` は自分より前の節の `id` |
| 節の数値 | `id` は 0 以上 10⁹ 以下の整数（実装レビュー P1-②：負の `id` で根元が2つになるのを防ぐ）。`pos` は各成分の絶対値 1,000 以下、`dir` は長さ 1（誤差 1e-6）。`length` は 0 以上 10 以下、`radius` は 0 より大きく 10 以下。`bornAge` は 0 以上 `age` 以下の整数。`bud` は真偽値（実装レビュー P1-①：検証を通ったデータを育てても範囲を外れないよう、上限を追加） |
| `boostUntil` | null か 0 以上 10⁹ 以下の整数 |
| `wire` | null か `{ until: 0 以上 10⁹ 以下の整数, axis: 長さ1（誤差1e-6）の数3つ, angle: 0〜π }` |
| 葉 | 全部で `SAVE_LIMIT_LEAVES` 以下。`size` は 0 より大きく 2 以下、`regrowAt` は null か 0 以上 10⁹ 以下の整数 |

範囲の検証を通った保存データなら、起動時の一括計算は「`lastTickAt` から今までの経過ぶん」で必ず終わる（`lastTickAt` は 2026 年以降の時刻に限られるため）。大きさの上限は localStorage の容量（約5MB）で決まるので、parse の前に文字列の長さは見ない。ファイル読み込み（FR-047）での大きさの上限は、そのプランで決める。

### 成長の中身（`step` の1回）

決定性（FR-008）のための約束：
- 節は `nodes` の並び（＝ `id` の小さい順）で処理する。手順3・4は、ステップの始めにあった節だけを対象にし、同じステップで生まれた節は次のステップから対象にする
- 乱数は、上限に届いて節や葉を足さないときも同じ回数だけ引いて捨てる（上限の近くでも乱数の並びがずれない）
- 上限に届いたら、並びの先（古い節）から優先して足し、残りは足さない
- 段階と伸びの基準値は、そのステップを進める前の `age` で決める。`age` 0（種）からの最初のステップは芽の値を使う
- 生まれた節の `bornAge` は、そのステップを進めた後の `age`（根元の節は 0）

手順：
1. `water = max(0, water − 4)`
2. 成長係数 `f = 0.3 + 0.7 × water / 100`（仮置き。#1）
3. 頂芽（`bud: true`）の節ごとに、確率 `ELONGATE[次数][段階]` で子の節を1つ足す（ADR-0002 の A：頂芽優勢の衰え）。次数は幹 0・幹から出た枝 1・その先 2 以上で、「子のうち `id` が最も小さいものは延長（次数そのまま）、ほかは横枝（次数 +1）」の規則で毎ステップ節の並びから求める（保存しない）。向き＝親の向き＋乱数のずれ（`1 − straightness` に比例）に、幹（次数 0）は上向きの偏り `TRUNK_UP` を足し、枝（次数 1 以上）は y 成分を `BRANCH_TARGET_Y` へ `BRANCH_PULL` の割合で寄せる（B：枝は水平へ）。長さ＝段階の基準値 × f × 乱数(0.8〜1.2)。伸びたら親の `bud` は false に、子は true。伸びなかった枝先は頂芽を持ったまま。乱数は伸びるかどうかにかかわらず枝先1つあたり4回引く。`id` は `nextId` から振り、`nextId` を1増やす
4. 側芽：「（生まれてから `LATERAL_WINDOW` ステップ以内、または `boostUntil > age`）かつ子が1つ以下、かつ頂芽がもう伸びている（`bud` が false）」の節は（最後の条件は 2026-10-24 実装時の判断：伸びていない枝先から横枝を出すと、横枝が延長と見なされて枝の次数が入れ替わるため）、確率 `p` で横枝を出す。`p = BRANCH_P[段階] × (0.5 + branchiness) × crowd`、`boostUntil > age` なら2倍。`crowd = (1 − 節の数 / MAX_NODES) / (1 + (節の数 / CROWD_HALF)²)`（2026-10-25 プランの変更：節が多いほど枝分かれを強く抑え、種による節の増え方の差を小さくする。変更前は `crowd = 1 − 節の数 / MAX_NODES`）。向きは親から `45° + spread × 35°` 開き（C）、方位は乱数。生まれた横枝の最初の節には、水平へ寄せる偏りはかけない（その先の延長からかける）。終わりの項で、上限に近づくほど枝分かれが減り、上限に普段から張りつかないようにする
5. 根元から位置を順に計算し直す（子の `pos` ＝ 親の先端）。太さは子のない節を `R_TIP` とし、先から根元へ `r親 = √(Σ r子²) + R_STEP` で計算し直す（子が1つでも親のほうが太く、根元へ向かって途切れずに太くなる）
6. 葉：枝先からの近さ `d`（子のない節を 0、親は子の `d` の最小 + 1）を求め、`d < LEAF_DEPTH`（5。E：葉の塊）の節で葉が1枚もなければ `LEAVES_PER_NODE`（3）枚付ける（大きさ＝`0.6 + 0.8 × leafSize`）。`d ≥ LEAF_DEPTH` になった節の葉は落ちる。葉は1枚ずつ足し、全体が `MAX_LEAVES` に届いた時点で止める（3,999 枚のところで2枚付けるべき節があれば、1枚だけ付けて 4,000 枚にする。葉の大きさは乱数を使わないので、決定性には響かない）（作者の回答 2026-10-21。節が上限に届いても枝先の葉は残る）
7. `age += 1`、`rngState` を更新
- 段階は `age` 121 以上がすべて成木なので、168 を超えたら基準値が成木で固定される（FR-006）

### 判断済みの論点

- 1ファイル出力は `vite-plugin-singlefile` を使う。`file://` で開いても動くよう、スクリプトはインラインの module にする（#8 の一部、#12）
- `?speed` があるときは、値にかかわらず保存キーを `bonsai.save.v1.speed` にする（#4）。値は「有限で 1 以上 86,400 以下の整数」に限り、それ以外は 1 として扱って画面の端に知らせる
- **speed の木は、1 フレームの間が 1 秒を超えたときも止まっていた扱いにする**（スリープやデバッガでの停止のように、タブが隠れずに描画だけが止まる場合。進めずに `lastTickAt` を今の時刻に直す。実装レビュー P1-③、しきい値は作者が決定 2026-10-25）。普段の木は、1 フレームの間が長くても要件どおりそのぶん進める
- **speed の木は、閉じている間・タブが隠れている間は進めない**。起動時とタブに戻ったときに `lastTickAt` を今の時刻に直す（作者の回答 2026-10-21。翌日開いて 86,400 ステップを一度に計算して固まるのを防ぐ）。普段の木（speed なし）は要件どおり不在分をすべて計算する
- `__bonsai.advance(hours)` はいまのキーの木を `floor(hours)` ステップ進め、`lastTickAt` は動かさない。「有限で 0 以上 10,000 以下」以外は何もせずに `console.warn`
- `__bonsai.state` は、いまの保存データの複製を返す（読み取り専用。調整のときに節の数などを見るため。実装時に足し、実装レビュー P1-⑨を受けて作者の指示でプランに記録 2026-10-25）
- `__bonsai.plant(seed?)` は speed の木だけを捨てて、指定の seed（省略時は `crypto.getRandomValues`）で植え直す。seed は 0 以上 2³²−1 以下の整数に限る。普段の木のときは何もせずに `console.warn`（作者の回答 2026-10-21）
- 長く放置したあとは、起動時にすべてのステップをその場で計算する。上限は設けない（#5）。節は最大 3,000 個なので、節 3,000 個の木から 720 ステップ（30日分）でも数秒以内に収まる見込み。テストで時間を測って確かめる
- 保存データが invalid のときは、ゲームを始めず理由を出す。作者が「退避して新しく始める」を選び、退避の書き込みに成功したときだけ、新しい種で `bonsai.save.v1` を書き直す。それ以外では保存データに一切書かない（FR-044。作者の回答 2026-10-21）
- 退避に一度失敗したあと成功したら、失敗の知らせを消す（実装レビュー P1-④）
- 書き込みに失敗したら、画面の端に警告を出し、その後も保存を試み続ける（FR-045）。種まきの保存に失敗したときも、木は植えて警告を出す
- **localStorage を読むこと自体が例外を出すとき**（`window.localStorage` に触れる・`getItem` が例外を出す）は、保存データがあるかどうかわからない。この起動のあいだは保存を一切しない（読めなかった木を上書きしないため）。画面の端に「保存できません。この木は閉じると消えます」と出し、種まきから遊べるようにする（テストレビューで挙がった論点。推奨案で決定 2026-10-21）
- 読み込めなかった（invalid の）あとは、自動保存（ステップのあと・隠れたとき・閉じるとき）も一切書かない
- E2E は `npm run build` の結果を `file://` で開いて、遊ぶときと同じ形で確かめる。時間は Playwright の `page.clock` の `fastForward` で進める（`runFor` で1フレームずつ回さない）
- 保存データの形（`nextId`、節の `boostUntil`・`wire` の中身、`parent` は `id` を指す）は ADR-0001（採択）で決めた（#6）。剪定のブースト（手順4の `boostUntil` の条件）はこの機能で成長の中に組み込み、剪定の機能では値を入れるだけにする
- 幹と枝の見分け方（評価のプランへの申し送り）：節の子のうち `id` が最も小さいものを「延長」とみなし、根元から延長をたどった連なりを幹とする。保存はしない

### 【要確認】

- （成長係数の式 #1 と調整値 #2 は 2026-10-25 に確定）
- （`file://` で開いたときの Firefox の localStorage は、2026-10-22 に実装順 3 で残ることを確かめた）

## 5. 新規テストケース

### 単体（`tests/unit/`、Node で実行）

Rng：
- 同じ seed → 同じ数列（1,000個）／`state` から作り直すと続きが一致／値は常に 0 以上 1 未満

Clock：
- 経過 6時間 → 6ステップ（SC-003）／3,599,999ms → 0・3,600,000ms → 1（境界の両側）
- 6時間59分 → 6ステップで、端数の59分が `lastTickAt` に残る
- 経過が負 → 0ステップで `lastTickAt = now`（SC-004）。`now` が `TIME_FLOOR` より前なら `lastTickAt = TIME_FLOOR`
- speed 3600 で 1,000ms → 1ステップ
- speed 7 で、16ms ずつ 10万回呼んだときの合計ステップ数が、一度に計算した値と一致する。`lastTickAt` は常に整数
- progress は 0 以上 1 未満

Tree（成長）：
- `createTree` 直後は age 0・段階「種」・節1つ（`id` 0、`parent` −1）・`nextId` 1。`now` が `TIME_FLOOR` より前なら `createdAt`・`lastTickAt` は `TIME_FLOOR`
- `createTree` → `step` で、節がちょうど2個、`id` 1 の `bornAge` が 1、`nextId` が 2。このステップで生まれた頂芽は同じステップの中では伸びない（FR-004・決定性の約束）
- 水分 100 → 96、0 → 0（下限）／`growthFactor(0)`=0.3、`(100)`=1.0
- 処理の順（FR-004）：同じ seed で `water` 4 と 0 の木を1ステップ進めると、新しい節の `length` が完全に一致する（どちらも水分を引いた後の 0 で f=0.3）
- 1節の伸び（FR-006）：段階ごとに、新しい節の `length` が「基準値 × f × 0.8〜1.2」に入る。`age` 169 と 500 の木では成木の基準値を使う
- 段階の境目 0・1・12・13・48・49・120・121・168・169。境目のステップで使う基準値は進める前の `age` の段階
- 性格値（FR-009）：0〜1 で seed ごとに決まる。同じ seed で性格値だけ差し替えると、次のとおり成長に効く
  - `leafSize`：葉の `size` が `0.6 + 0.8 × leafSize` と一致
  - `spread`：横枝の最初の節が親から開く角度が `45° + spread × 35°` と一致
  - `branchiness`：1 のほうが 0 より横枝が多い
  - `straightness`：1 のほうが 0 より向きのずれの平均が小さい
- 決定性（SC-010）：同じ seed で 200 ステップ進めた2本の木が完全に一致。seed が違えば一致しない
- `advance(n)` → 保存 → 読み込み → `advance(m)` と、`advance(n+m)` の節の一覧が完全に一致する
- 上限（FR-012）：
  - 節 2,999 個・頂芽が複数ある木を1ステップ → ちょうど 3,000 個。足されたのは `id` が最も小さい頂芽の子
  - 葉 3,999 枚で、葉を2枚付けるべき節がある木 → 1枚だけ付いて 4,000 枚。4,000 枚の木 → 増えない
  - 上限に届いていてもいなくても、1ステップで引く乱数の回数が同じ（上限の前後で以後の乱数の並びがずれない）
- `id` は重複せず、`nextId` は常にどの `id` よりも大きい
- 子の `pos` は親の先端と一致／親の太さは子のどれよりも太い
- 葉は枝先から `LEAF_DEPTH` 節未満の節にだけ付く。節が上限に届いた木を 100 ステップ進めても葉が 0 枚にならない
- `boostUntil > age` の節は、生まれて `LATERAL_WINDOW` を過ぎていても横枝を出しうる（同じ seed で、`boostUntil` が null の場合より横枝が増える）
- 目安：seed 3つで age 168 の節の数が 150〜1,500、age 336 で 3,000 未満（調整値 #2 を変えたら一緒に直す、とテストのコメントに書く）
- 頂芽優勢の衰え（ADR-0002 の A）：成木の幹だけの木（頂芽1つ）を 100 ステップ進めても、伸びた節は 50 未満。伸びなかったステップのあとも枝先は頂芽を持ったまま。芽の幹は毎ステップ伸びる（2026-10-25 の調整で、苗の幹は毎ステップは伸びなくなった）
- 枝は水平へ（B）：seed を固定して 168 ステップ育てた木で、次数 1 以上の延長の節の `dir.y` の平均が、幹の節の `dir.y` の平均より 0.3 以上小さい
- 側芽の窓（D）：生まれて 12 ステップの節は横枝を出しうる（400 節・苗の段階で1ステップ進めて1本以上）。13 ステップの節は出さない（0本）
- 混み具合（2026-10-25 プランの変更）：`crowdFactor` は節 0 個で 1、`CROWD_HALF` 個で `0.5 × (1 − CROWD_HALF / MAX_NODES)`、上限以上で 0、節が多いほど単調に減る。seed 6つで age 168 の節が 150〜1,500
- 168 ステップで段階「成木」

Tree と Store の結合【P0】：
- 成長で作った保存データは必ず自分の検証を通る。seed 0・2³²−1・任意の1つで、`createTree` 直後・1・48・121・168 ステップ後・節が上限に届いてからさらに 100 ステップ後の木を、それぞれ `JSON.stringify` → `parseSave` に通すと、すべて `kind:'ok'` で元の値と完全に一致する（`rngState` が負になる、`radius` が 0 になる、`bornAge` が `age` を超える、などの食い違いを見つける）

計算時間（`tests/unit/perf.test.ts`。閾値に余裕を持たせる）：
- 節 3,000 個・葉 4,000 枚に近い木から 720 ステップの計算が 5 秒未満

Store：
- 保存 → 読み込みで同じ値／未保存 → empty
- 壊れた JSON・`version` 2 → invalid（`raw` に元の文字列）で `setItem` を呼ばない
- 形の不正 → invalid：項目が足りない（`nextId` がない）、型が違う（`age` が `"1"`）、直下が `null`・配列・数値、`nodes` が空、`id` が小さい順でない、先頭が根元でない、根元が2つ、`parent` が存在しない・後ろの節を指す、`id` の重複、`bornAge` が `age` より大きい、`bud` が真偽値でない、`dir` の長さ 0
- 有限でない数 → invalid：`"pos":[1e999,0,0]`・`[-1e999,0,0]`（JSON の文字列に NaN は書けないため、parse すると Infinity になる書き方で確かめる）
- 範囲の境界の両側：

|---|---|---|
| `water` | 0・100 | −1・101 |
| `traits` | 0・1 | −0.0001・1.0001 |
| `age` | 0・1 | −1・1.5 |
| `seed` | 0・2³²−1 | −1・2³² |
| `rngState` | 0・2³²−1 | −1・2³² |

| `lastTickAt` < `createdAt` | ok（大小は見ない） | — |
| 節の数 | 3,001（成長の上限を超えても読める）・20,000 | 20,001 |

- `setItem` が例外を出す → `{ok:false}` を返し、例外を外に出さない
- `backupBroken` は `bonsai.save.v1.broken.<UTCミリ秒>` に元の文字列をそのまま書き、`bonsai.save.v1` には触らない。書き込みに失敗したら失敗を返す
- 通常のキーと speed のキーが混ざらない

起動と画面の処理（`src/ui/app.ts` の、DOM に触れない関数）：
- 起動：偽の時刻と偽の storage で「保存して6時間後に起動」→ age が 6 増える（SC-003）
- 【P0】時計が種まきより前に戻る：時刻 T で種をまいて保存 → T−1日で起動して保存 → `load` すると `kind:'ok'`、age・節・水分は変わらない（SC-004）
- speed の木：保存して24時間後に起動 → age は増えず、`lastTickAt` が今の時刻
- speed の起動は `bonsai.save.v1` を読みも書きもしない（FR-013）
- タブに戻ったとき（FR-011・FR-013）：普段の木が隠れて 6 時間 → age が 6 増える。speed の木が隠れて 1 時間 → age は変わらず `lastTickAt` が今の時刻
- 自動保存の時機（FR-043）：ステップが進んだフレームのあと・隠れたとき・閉じるときに、今の状態を `setItem` で書く
- 読み込めなかったあと（FR-044）：invalid で起動したあと、隠れたとき・閉じるときの処理を呼んでも `setItem` を呼ばない
- localStorage を読むと例外が出る（`getItem` が例外を出す偽の storage）：起動はエラーにならず「保存できません」の状態になる。種まき・ステップのあと・隠れたときのどれでも `setItem` を呼ばない
- 種まきの保存に失敗（FR-045）：木は植わり、警告の状態になる
- 【P0】退避（FR-044）：確認を拒否 → storage のキーの一覧と中身が変わらず、種まきの状態にならない。`bonsai.save.v1.broken.*` への書き込みだけが失敗 → `bonsai.save.v1` は元の文字列のまま、失敗の知らせが出て、種まきの状態にならない
- `?speed` の値の解釈：`1`・`3600`・`86400` → その値。`0`・`-1`・`abc`・`1.5`・`Infinity`・`86401` → 1 と知らせ。どれも speed のキー
- `advance`：`-1`・`NaN`・`Infinity`・`10001` → 何もしない。`0` → 0 ステップ。`1.5` → 1 ステップ。`10000` → 10,000 ステップ（成長の関数を差し替え、呼ばれた回数で確かめる）。どの場合も `lastTickAt` は変わらない
- `plant`：普段の木では何もしない。speed の木では指定の seed で age 0 に戻る。seed `0`・`2³²−1` → 植え直す。`-1`・`2³²` → 何もしない

実装レビュー（2026-10-25）の P1 で足した単体テスト：
- Store：`pos`・`length`・`radius`・`age`・`nextId`・`boostUntil`・`regrowAt`・`wire.until` の上限ちょうどは ok・超えると invalid。`dir` の長さが 1 から 1e-6 以内は ok・外れると invalid。負の `id` は invalid
- 起動と画面の処理：speed の木で 1 フレームの間が 1 秒を超えたら進めない・1 秒以内なら進む・普段の木は長くても進む。退避に失敗したあと成功したら知らせが消える。保存失敗のあと成功したら警告が消える。壊れた保存データのあと `plant`・`replant`・`advanceHours` でも書かない。退避に失敗したあと `plant` を呼んでも書かない
- E2E：speed の木で時計を進める場面は、0.5 秒ずつ刻んで進める（1 フレームの間が 1 秒を超えると止まっていた扱いになるため）

### E2E（`e2e/core-growth.spec.ts`、chromium・firefox、`dist/index.html` を `file://` で開く）

- 初回起動で「種をまく」→ 押すと localStorage に `bonsai.save.v1` ができ、age 0（SC-001 の保存データの部分、受け入れシナリオ1-1）
