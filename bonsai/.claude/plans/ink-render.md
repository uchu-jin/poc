状態：実装済み（2026-10-25）｜元資料：docs/requirements/requirements.md（ストーリー5・1、FR-010・011・026（土の色の部分）・034・035・037〜041、付録 A.4、SC-001（鉢の表示の部分）・SC-013・SC-014）
関連ADR：なし（判断はどれも Renderer の中に閉じ、後から変えても保存データや成長には響かないため。ADR-0001・0002 は前提として読む）

## 1. 概要

Three.js（CDN から読む）で、和紙の背景・墨の濃淡と筆のような輪郭線の枝・墨のにじみの葉・鉢と土を描き、成長を1時間かけて伸びて見せる。右ドラッグ・ホイール・中ドラッグ・R のカメラ操作と、枝・葉・土の当たり判定（後の手入れの機能が使う）を作る。画面の配置（FR-034）は、後の機能で作る部分を空の枠として置く。
Three.js が読めないときは、和紙の画面に一言出し、成長と保存はそのまま動かす。重くて 30fps を保てないときは、画面の密度（pixel ratio）を 1 に下げる。

## 2. 背景

- いまは `?debug` の 2D の姿しかなく、普段の画面には木が出ない。剪定・針金・葉摘み・水やり・評価は、どれも 3D の画面と当たり判定の上に乗る
- 作者の回答（2026-10-25）：
  - Three.js は CDN から読む（要件どおり）
  - 書体は Shippori Mincho（Google Fonts）。読めなければ端末の明朝体
  - 見た目は要件 A.4 を一通り作る
  - Three.js が読めないときは和紙の画面に一言
  - 伸びの補間は「新しい節が1時間かけて伸びる」（見た目は実際の木より最大1ステップ遅れる）
  - カメラは、自分で動かしていない間は木の大きさに合わせて引く
  - 画面の後の機能の部分は、場所だけ用意する
  - `?debug` の 2D の姿は、`?debug` のときだけ端に小さく出す（fps も出す）
  - 枝の当たり判定は、画面で数px（6px）の幅を持たせる
  - 30fps を保てないときは、解像度（pixel ratio）を下げる
  - 見た目は、比較ページのスクリーンショットを作者が見て決める（画像の差分テストは作らない）

## 3. 詳細設計

### 変更するファイル（すべて `bonsai/` の中）

依存と読み込み：
- `package.json` - devDependencies に `three` 0.186.1（2026-09-24 公開）と `@types/three` 0.186.0（2026-09-11 公開）を正確な版で足す。`three` は開発サーバーと単体テストのためだけに入れ、ビルドには含めない
- `vite.config.ts` - `build.rollupOptions.external: ['three']`。ビルド結果の `import 'three'` は、index.html の import map で CDN に向ける
- `index.html` - import map：`"three": "https://cdn.jsdelivr.net/npm/three@0.186.1/build/three.module.js"`。Google Fonts の Shippori Mincho（`display=swap`）。import map の `integrity` に、**読み込まれる URL それぞれ**（`three.module.js` と、そこから相対パスで読まれる `three.core.js` など。一覧は実装順 2 で確かめる）の sha384 を書く。ハッシュは CDN から取ってきた内容ではなく、`node_modules/three/build/` の同じ名前のファイル（package-lock の integrity で検証された npm の中身）から計算する（セキュリティレビュー P1-1・P1-2）
- `src/style.css` - 書体を `'Shippori Mincho', 'Hiragino Mincho ProN', 'Yu Mincho', serif` に

画面の組み立て：
- `src/main.ts` - 描画は `import('./render/renderer')` の動的 import で読み込み、失敗したら `src/ui/render-failed.ts` の知らせを出す（成長・保存・左上の表示はそのまま動く）。Renderer の初期化（WebGL の文脈を作るところ）で投げた例外も同じ知らせに流す。vite-plugin-singlefile は動的 import を1つのバンドルに展開するため、renderer の中の `import 'three'` がバンドル先頭の静的 import になると、CDN に届かないときに全体が動かなくなる。実装順 2 で dist の出力を確かめ、そうなっていたら `three` 自体を `await import('three')` で読む（外部の動的 import は出力でも動的に残る）形にする（セキュリティレビュー P1-3）。毎フレーム、Game の `tick` のあとに Renderer の `frame(now)` を呼ぶ
- `src/ui/layout.ts` - FR-034 の枠：右上（樹形スコア）・右下（水分）・下中央（ツールバー）・左下（設定）を、薄い文字の空の枠として置く（中身は各機能で入れる）
- `src/ui/render-failed.ts` - 「3D の部品を読み込めませんでした。ネットにつないで開き直してください」（textContent）
- `src/ui/debug-view.ts` - `?debug` のときだけ、右の端に小さく 2D の姿と数値、fps を出す

描画（`src/render/`。Three.js を使うのはここだけ）：
- `renderer.ts` - WebGLRenderer・シーン・カメラ・リサイズ・`frame(now)`。保存データが変わったとき（ステップ・植え直し）だけ枝と葉の形を作り直し（FR-040）、毎フレームは uniform（現在の age・進み具合・時刻）だけを更新する
- `background.ts` - 画面全体の板に和紙のシェーダー：生成り色・繊維のような淡いノイズ・四隅をわずかに暗く（A.4）
- `branch-mesh.ts` - 全部の節を1つの BufferGeometry にまとめる（節ごとに6角の円柱）。頂点属性：節の位置（`nodeIndex`）、`bornAge`、根元からの深さ（墨の濃さ用）、輪郭線の太さの乱数（節の id から決める）
- `ink-material.ts` - 枝のシェーダー：左上からの1方向の光を3段階に区切り、墨の濃度に割り当てる。根元ほど濃く、枝先ほど淡い。影は落とさない（A.4）
- `outline.ts` - 輪郭線：同じ形を裏返して法線方向に膨らませて描く（inverted hull）。線幅 = 基準 × (1 + 節ごとの乱数)（A.4）
- `leaves.ts` - 葉：InstancedMesh の板を常にカメラへ向ける。墨のにじみの模様は、起動時に canvas で手続き的に作ったテクスチャ（ファイルを足さない）。`INK_ACCENT`（初期値オフ）のときだけごく薄い緑（FR-039）
- `pot.ts` - 濃い灰色の簡素な鉢と土。土の色は水分で、薄い茶灰（0）〜濃い茶灰（100）（FR-026 の土の色の部分）
- `growth-view.ts`（Three.js に依存しない計算）：
  - 伸びの補間（FR-010）：`bornAge === age` の節（最後のステップで生まれた節）だけ、長さ × `progress`（0〜1、`clock.progress`）で描く。その節の葉も同じ割合で大きくする。保存データには入れない
  - 墨のにじみ（FR-038）：Renderer が節を初めて描いた時刻を、節の id ごとにメモリに持つ（保存しない）。その時刻から1秒かけて淡い墨から本来の濃さへ。起動時にすでにある節はにじませない
- `camera-controls.ts` - 自前の操作（OrbitControls は使わない。右・中ボタンの割り当てとクランプを要件どおりにするため）：
  - 右ドラッグ：鉢の中心まわりに回転。横は360度、仰角は −10〜80度（FR-035）
  - ホイール：ズーム。距離は鉢と木が収まる距離の 0.3〜3 倍
  - 中ドラッグ：見る高さを上下（0 〜 木の高さ）
  - R：初期位置（正面）に戻す
  - 右クリックのメニューは出さない
  - 自分で動かしていない間は、木の大きさ（鉢と木の外接球）に合わせて引きを合わせる。動かしたらやめ、R で戻すと再開
  - 正面は、カメラの初期の向き（+z から −z を見る、仰角 15°）。評価（FR-033）が使うので `FRONT_AZIMUTH` として定数にする
- `camera-math.ts`（Three.js に依存しない計算）：仰角のクランプ、ズームのクランプ、外接球から引きの距離を出す式
- `picking.ts` - 当たり判定（後の手入れの機能が使う）：
  - 枝：各節の線分を画面に投影し、カーソルからの距離が 6px 以内のもの。重なったら手前、同じくらいなら細いほう（枝先）を優先
  - 葉：葉の中心を画面に投影し、葉の見た目の半径以内
  - 土：カーソルの光線と土の面（y = 0）の交点が鉢の内側
  - 返す値：`{ kind: 'branch', nodeId } | { kind: 'leaf', nodeId, leafIndex } | { kind: 'soil' } | null`
- `pick-math.ts`（Three.js に依存しない計算）：画面上の点と線分の距離、優先順位の決め方
- `window.__bonsai.pickAt(clientX, clientY)` - 確認用に当たり判定の結果を返す（E2E で使う。dist にも残す）
- `window.__bonsai.camera` - 確認用に、いまのカメラの azimuth・elevation・distance・targetY を返す（読むだけ。E2E でカメラの操作を確かめるため。テストレビュー P0-1 を受けて追加）

性能（SC-014）：
- `renderer.ts` は pixel ratio を `min(devicePixelRatio, 2)` で始め、直近5秒の平均が 30fps を下回ったら 1 に下げる（一度下げたらその起動の間は戻さない）。`?debug` の fps の表示に今の pixel ratio も出す
- 枝は1つの描画、輪郭線も1つ、葉は InstancedMesh 1つ、背景1つ、鉢と土で、描画の呼び出しは10回未満に収める

### 判断済みの論点

実装時の判断（2026-10-25）：
- 描画の時刻（にじみ）は、ページを開いてからの `performance.now()` を Renderer の中で使う。`Date.now()` の大きな値は 32 ビットの小数で約128秒単位にしか表せず、にじみが進まなくなったため
- 形を作り直すたびに新しい形に差し替え、古い形を捨てる（`dispose`）。捨てないと GPU のメモリが溜まり、早送りで毎秒作り直すとブラウザが重くなった（作者の報告）
- fps の判定は、前のフレームとの間が 300ms を超えたら記録をやり直す。見えていないペインやタブで描画が絞られた間の低い fps で、pixel ratio を下げないため
- `InkFade` は、起動時の節を「ずっと前に見た」と記録する。記録しないと、次に作り直したとき起動時の節までにじみ直すため
- 鉢は、作者の指摘（鉢が大きい）で、半径 0.32・深さ 0.16 に小さくした。成長の単位（鉢の直径＝1）と成長の数値は変えない
- 中ドラッグは、画面で上へドラッグすると見る高さが上がる向き。見る高さの初期値も 0〜木の高さに収める（E2E で見つかった不具合）
- 見た目の調整 1回目（作者の指摘 2026-10-25）：葉は淡い灰色（0.3）・不透明度 0.6 の、70個の小さなしみが集まった模様にし、葉ごとに向きを回す。幹の輪郭線の太さの揺らぎは、節ごとの乱数ではなく位置に沿ったなだらかな波にする（ギザギザの帯を消す）。節の先端を太さの 0.6 倍だけ先へ延ばして重ね、つなぎ目の白い筋を消す。鉢は枝と同じ3段階の墨の陰影・刷毛の縦の筋・輪郭線にする
- `?debug` の右端には、fps・pixel ratio のほかに、描画の呼び出しの回数・作り直しの回数・GPU に残っている形の数も出す（重さの確認のため）

- Three.js は CDN（jsDelivr）から import map で読む。版は `three@0.186.1` に固定し、`package.json` の devDependencies の版と一致することを単体テストで確かめる（版を上げ忘れて開発と本番がずれるのを防ぐ）（#8）
- import map の `integrity`（SRI）は、読み込まれる URL それぞれに付ける。未対応のブラウザで無視されるだけなら付けたままにし、付けると読み込みが壊れるときだけ外して理由をここに書く（セキュリティレビュー P1-1・P1-2）
- 書体は Shippori Mincho。読めなければ端末の明朝体（#9）
- Three.js が読めないときは和紙の画面に一言。動的 import にして、成長と保存は止めない（#10）
- 伸びの補間は、最後のステップで生まれた節を1時間かけて伸ばす。見た目は最大1ステップ遅れる（作者の回答）
- 枝は全節を1つの BufferGeometry にまとめ、形が変わったときだけ作り直す。伸びとにじみは頂点属性と uniform でシェーダーが行う（毎フレーム作り直さない。FR-040）
- カメラの操作は自前で書く。OrbitControls は使わない（右・中ボタンの割り当てと仰角 −10〜80度のクランプ、木に合わせた自動の引きを要件どおりにするため）
- 当たり判定は Three.js の Raycaster ではなく、画面に投影した線分との距離で行う（枝先は 1px 未満の細さで、形そのものへの Raycast では当たらないため）
- 葉の模様は起動時に canvas で作る（1ファイル配布のまま、画像ファイルを足さない）
- 見た目は自動テストで判定しない。3つの seed × 1・7・30日目のスクリーンショットで作者が決める
- 切った枝が落ちる演出（A.4）は、剪定の機能で作る

## 5. 新規テストケース

単体（`tests/unit/`、Node で実行。`three` は devDependencies から読める）：
- 版の一致：`index.html` の import map の `three@x.y.z` と `package.json` の `three` の版が一致する
- 中身の一致：import map の各 `integrity` が、`node_modules/three/build/` の同じ名前のファイルの sha384 と一致する（セキュリティレビュー P1-2）
- 伸びの補間（`growth-view.ts`）：`bornAge === age` の節は `progress` 0 → 長さ 0、0.5 → 半分、1 未満の最大値 → ほぼ全長。`bornAge < age` の節は常に全長。age 0（種）でも壊れない
- 墨のにじみ：初めて描いた時刻から 0ms → 淡い墨の濃さ、500ms → 中間、1,000ms 以上 → 本来の濃さ。起動時にあった節は最初から本来の濃さ
- カメラの計算（`camera-math.ts`）：仰角 −10 と 80 はそのまま、−10.1 と 80.1 は境目にクランプ。ズームは収まる距離の 0.3 倍と 3 倍はそのまま、0.29 倍は 0.3 倍に、3.01 倍は 3 倍にそろう。見る高さは 0 と木の高さちょうどはそのまま、−0.01 は 0 に、木の高さ +0.01 は木の高さにそろう。種（木の高さがほぼ 0）でも高さの範囲が反転しない。外接球の半径が大きいほど引きが遠い。種（節1つ）でも 0 にならない（テストレビュー P0-2）
- 当たり判定の計算（`pick-math.ts`）：線分からの距離 6px ちょうどは当たり、6.01px は外れ。線分の端より外の点は端までの距離。重なったら手前、同じ深さなら細いほう
- 枝の形（`branch-mesh.ts`）：節 n 個で頂点数が n × 1節あたりの頂点数。`nodeIndex`・`bornAge` の属性が節ごとにそろう。長さ 0 の根元の節でも NaN を出さない。節 3,000 個で作れる
- 土の色（`pot.ts` の色の関数）：水分 0 で薄い茶灰、100 で濃い茶灰、50 で中間。範囲外（−1・101）は端にそろえる

E2E（`e2e/ink-render.spec.ts`。`dist/index.html` を `file://` で開く。CDN に届くことが前提）：
- 種をまくと、3D の canvas が出て、WebGL の文脈が作られ、`pageerror` が 0 件（SC-001 の鉢の表示）
- jsDelivr への通信を `page.route` で止めると、「3D の部品を読み込めませんでした」が出て、種まき・左上の表示・保存が動く（#10・セキュリティレビュー P1-3）
- `__bonsai.pickAt` で、画面の中心の少し下（土）を指すと `soil`、何もないところは `null`
- カメラの操作（ストーリー5-1、FR-035。テストレビュー P0-1）：`window.__bonsai.camera`（azimuth・elevation・distance・targetY を読むだけ）で確かめる。右ドラッグで azimuth が変わる。ホイールを前に1回で distance が縮む。中ドラッグで上へ targetY が上がる。そのあと R で4つの値がすべて初期値に戻る（スクリーンショットの一致では比べない。伸びの補間とにじみで毎フレーム絵が変わり、揺れるため）
- FR-034 の枠が5つ（左上・右上・右下・下中央・左下）ある
- `?debug` のときだけ右の端に 2D の姿と fps が出る

手動（作者）：
- 3つの seed × 1・7・30日目のスクリーンショットで見た目を見る（実装順 10）
- 節 3,000・葉 4,000 の木で fps を見る（SC-014。`?debug` の fps の表示）
- Edge で一度開く（SC-013）
