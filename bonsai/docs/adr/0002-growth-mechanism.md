# ADR-0002：成長の仕組み（枝先の伸び方・枝の向き・葉の付き方）

状態：採択 ｜ 起票：2026-10-24 ｜ 決定：2026-10-24 ｜ 決定者：作者
関連：docs/requirements/requirements.md の FR-004・FR-006・FR-009・付録 A.2、12章 #1・#2／.claude/plans/core-growth.md（実装順 9）／ADR-0001

## 1. 問い

「土台と成長のコア」を実装して育ててみると、どの種でも、枝の少ない一本の柱のような木にしかならなかった（168ステップでも100日でも）。調整値（数値）を変えるだけで直すか、成長の仕組み（1ステップの処理）も変えるかを決める。木の形はゲームの見た目と評価（4章）の土台で、遊び始めてから変えると、育てている木の育ち方が変わってしまうため、今決める。

前提・制約：
- 1ステップの処理の順番（FR-004）は変えない。保存データの形（ADR-0001）も変えない
- 同じ seed と同じ手入れで同じ木になる（FR-008）
- 節 3,000・葉 4,000 の上限（FR-012）。成木（168ステップ）のあとも伸びはゆるやかに続く（8.2）
- 剪定・針金で樹形を整えるのがゲームの中心。放っておいた木が完成形である必要はない

判定基準：
- 正面から見て、幹と、横に張る枝と、枝先の葉の塊が見分けられる（盆栽らしい骨格）
- 7日目に節が数百個（上限に届かない）。上限に届くのは早くても2週間以上あと
- 性格値（FR-009）で木ごとに形が変わる
- 保存データの形を変えない

## 2. 選択肢

| #   | 選択肢 | 概要 | 出どころ | 見立て |
| --- | ------ | ---- | -------- | ------ |
| A   | 数値だけで調整する | 枝分かれを増やす、開き角を大きくする、幹の伸びを短くする | AI（claude-opus-5-5） | 不採用（V-01） |
| B   | 仕組みも直す（A〜E） | 下の5つを入れる | AI（claude-opus-5-5） | 採用（V-01・V-02） |

選択肢 B の中身：
- **A. 頂芽優勢の衰え**：枝先が毎ステップ必ず伸びるのをやめ、枝の次数（幹 0、幹から出た枝 1、その先 2 以上）と段階に応じた確率で伸びる。幹は若木から伸びが落ち、成木ではほぼ止まる
- **B. 枝は水平へ**：上向きの偏りは幹だけにかける。枝は水平より少し上の向きへ寄っていく
- **C. 開き角を広げる**：横枝の開き角を 20〜60° から 45〜80° にする
- **D. 枝分かれの見直し**：側芽が枝になれる期間を 6 → 12 ステップにし、確率を合わせ直す
- **E. 葉の塊**：葉の付く範囲を枝先から 3 節 → 5 節、1 節あたり 2 → 3 枚にする

枝の次数は、ADR-0002 で新しく保存する値ではない。「子のうち id が最も小さいものは延長、ほかは横枝」という規則で、毎ステップ節の並びから求める（プランの「幹と枝の見分け方」と同じ規則）。

### V-06（2026-10-25）混み具合で枝分かれを抑える式（作者の指示でプランの変更）

## 4. 決定
（状態を「提案」にするときに AI が推奨を書き、作者が採択するときに確定する）

作者が AI の推奨どおり採択した（2026-10-24）。

- 採用：選択肢 B（仕組みの A〜E を入れる）。数値は V-02 で残した値から始め、実装順 9 で作者と決め直す
- 追記（2026-10-25、作者の指示）：次の2つも採用する。どちらも検証ログにある仕組みの変更で、実装レビュー（P1-②）で「決定に書かれていない」と指摘されたため追記した
  - 頂芽がまだ伸びていない節（`bud: true`）からは横枝を出さない（V-03）
  - 混み具合で枝分かれを抑える式 `crowd = (1 − 節の数 / 3000) / (1 + (節の数 / CROWD_HALF)²)`、`CROWD_HALF` = 500（V-06）
- 理由：
  - 盆栽らしい骨格 → 幹・横枝・葉の塊が見分けられた（V-02）。今の仕組みでは数値をどう変えても柱だった（V-01）
  - 上限に届く時期 → 7日目は 232〜693 節。上限は 30〜100日目（V-02）
  - 保存データの形を変えない → 枝の次数は節の並びから求め、保存しない
- 受け入れるトレードオフ：プランの「成長の中身」と単体テストの一部（性格値の straightness・spread の確かめ方、育ち方の目安）を書き直す。1ステップで引く乱数が枝先1つあたり 3 → 4 回に増える
- 見直す条件：剪定・針金の機能で遊んでみて、放っておいた木の形が手入れの邪魔になるとき／評価（4章）の「樹冠の輪郭」で点が極端に偏るとき

## 5. 選ばなかった選択肢

### 選択肢 A：数値だけで調整する
- 選ばなかった理由：枝分かれを増やすと上限に早く届くだけで、枝が上を向いて伸びる性質は数値では変わらない（V-01）
- 採らないことで失うもの：プランと単体テストの書き直しが要らず、1ステップの処理が単純なまま
- 再検討する条件：なし（仕組みの案 B の中で、数値の調整は続ける）
