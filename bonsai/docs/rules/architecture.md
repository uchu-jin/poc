# アーキテクチャルール

プランレビュー・実装レビュー・リファクタリングの判定基準。プロジェクトに合わせて育てる。

## 構成
- 部品単位でまとめる：`src/core/`（Rng・Clock・Tree・Evaluator・Store）、`src/render/`（Renderer）、`src/ui/`（UI）。要件定義 付録 A.6
- `src/core/` は Three.js・DOM・`window` を import しない。時刻は引数で受け取り、乱数は Rng を通す（`Math.random()`・`Date.now()` を使わない）
- 描画の都合の値（補間・墨のにじみ・落下演出）は Renderer に閉じ、保存データに入れない
- 1ファイル1責務。300行を超えたら分割を検討する
- 依存の向き：UI → Renderer → core。core から外へは依存しない
- localStorage・ファイルの読み書きは Store に閉じ込め、テストで差し替えられるようにする

## 実装
- 既存の仕組み（認可、バリデーション、エラーハンドリング）を流用し、機能専用の仕組みを新設しない
- 純粋関数にできるロジック（変換・正規化・計算）は副作用から切り離す
- 同じ処理が3箇所に現れたら集約する
- 調整用の数値（`GROWTH_STEP_MS`、水分の増減、上限、`INK_ACCENT` など）は1か所の定数にまとめる。シークレットは持たない

## データ
- 保存データ（`bonsai.save.v1`）の形を変えるときは ADR を書き、`version` を上げる。古い版を黙って読み替えない
- 毎フレームの描画で、節・葉の数に比例したオブジェクトの生成をしない。形が変わったときだけ作り直す（FR-040）
- 外部から来た値は境界で検証・正規化してから内部に渡す
