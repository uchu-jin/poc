# テストルール

テスト網羅レビュー・実装レビューの判定基準。

- 要件定義の受け入れシナリオ1つにつき、最低1つのテストを対応させる
- 境界値は両側を書く（上限ちょうど／上限+1、0件／1件）
- 異常系を書く：空、不正形式、上限超過、外部サービスの失敗
- 先に失敗（Red）を確認してから実装する。最初から通るテストは疑う
- 外部サービスはモックする。単体テストからネットワークに出ない
- スコープ外の振る舞いをテストしない
- テスト名は「〜のとき〜となる」の形で、何を保証するかを読めるようにする

## このプロジェクトで足すこと
- 時間の経過は偽の時刻を渡して確かめる。実時間を待たない
- 乱数を使う処理は seed を固定して確かめる。同じ seed・同じ手入れで節の一覧が一致することを確かめる（SC-010）
- `src/core/` の単体テストは Three.js なしの Node で動かす
- 見た目（水墨画風の表現）は自動テストで判定しない。スクリーンショットを作者に見せて確認する
- 上限（節3,000・葉4,000・針金8本・水分0/100）は両側の境界を書く
