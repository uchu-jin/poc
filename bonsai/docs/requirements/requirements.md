# 要件定義：盆栽育成ゲーム（bonsai）

状態：ドラフト｜作成日：2026-10-19｜最終確認者：【要確認】

作者が書いた要件定義書（2026-10-19）を、この形式に移したもの。数値のうち聞き取りで決まっていないものは「（仮置き）」と書いた。

## 1. 概要

PCブラウザで動く3D盆栽ゲーム。種から実時間で約1週間（1時間に1ステップ、168ステップ）かけて木に育ち、プレイヤーが剪定・針金・葉摘み・水やりで樹形を整える。木の形は種ごとにランダムで、和紙に墨で描いたような見た目にする。樹形は5つの指標で100点満点で採点するが、勝ち負けはない。

## 2. 背景・課題

- 対象ユーザー：作者1人（個人利用、アカウントなし）
- 現状：本物の盆栽は場所・時間・手間がかかり、気軽に樹形づくりを試せない
- 課題：PC の前にいる合間に、放置しておけば育ち、ときどき手入れして形を整える楽しみがほしい。手入れの良し悪しを目安として数値で知りたい

## 3. ユーザーとロール

| ロール | 説明 | できること |
|---|---|---|
| プレイヤー | 作者本人。PC（マウス＋キーボード）で遊ぶ | 種をまく、育つのを眺める、4つのツールで手入れする、スコアを見る、データを書き出す・読み込む |

## 4. ユーザーストーリー

優先度：P1＝MVPに必須／P2＝早期に欲しい／P3＝将来

### ストーリー1：種をまき、実時間で育つのを見る（P1）

プレイヤーとして、放置していても木が育つ楽しみのために、種をまいて実時間で育つ様子を見たい。

**なぜこの優先度か**：ゲームの核。手入れも評価も、育つ木がなければ成り立たない。

**受け入れシナリオ**
1. **Given** 保存データがない、**When** 起動する、**Then** 土だけの鉢と「種をまく」ボタンが出る。押すと `age` 0 の種が植わり、保存データができる
2. **Given** `?speed=3600` で開いた、**When** 約168秒待つ、**Then** 種から成木まで育つ
3. **Given** 木を育てている、**When** 閉じて6時間後に開く、**Then** 6ステップぶん成長した状態で表示される
4. **Given** 端末の時計が前回より過去に戻っている、**When** 起動する、**Then** 成長は巻き戻らず、エラーも出ず、`lastTickAt` だけが現在時刻に直る
5. **Given** 同じ `seed`、**When** 同じ手入れを同じ `age` で同じ順に行う、**Then** 同じ形の木になる

### ストーリー2：剪定と針金で樹形をつくる（P1）

プレイヤーとして、自分好みの樹形にするために、枝を切ったり針金で曲げたりしたい。

**なぜこの優先度か**：盆栽らしさの中心。木の構造そのものを変える操作で、保存データと評価に直結する。

**受け入れシナリオ**
1. **Given** 枝のある木、**When** はさみで枝をクリックする、**Then** その節から先の枝と葉がすべて消え、切り口直下の側芽が以後24ステップ枝になりやすく（2倍）なる
2. **Given** はさみを選んでいる、**When** 幹の根元の1節をクリックする、**Then** 切れない
3. **Given** 太さが上限以下の枝、**When** 針金でドラッグする、**Then** その節から先がドラッグ方向に曲がり、24ステップ形を保ち、その後は外れて形が定着する
4. **Given** 針金を当てた枝、**When** 1節で45度または枝全体で120度を超えて曲げる、**Then** 枝が折れ、剪定と同じ扱いになる
5. **Given** 直前に手入れをした、**When** Ctrl+Z を押す、**Then** その1操作が取り消される。次のステップが進んだあとは取り消せない

### ストーリー3：葉摘みと水やりで木を世話する（P1）

プレイヤーとして、木の調子を整えるために、葉を摘んだり水をやったりしたい。

**なぜこの優先度か**：放置育成の手ごたえ（水分）と、葉を小さくする盆栽の技法の両方を担う。

**受け入れシナリオ**
1. **Given** 葉のある木、**When** 指で葉をクリックする（またはなぞる）、**Then** 葉が消え、2ステップ後にもとの0.9倍の大きさで生え直す（最小0.5倍）
2. **Given** 水分が60、**When** じょうろで土をクリックする、**Then** 水分が100になり、土の色が濃くなる
3. **Given** 水分が100、**When** 土をクリックする、**Then** 水分は変わらず、染み込む表示だけが出る
4. **Given** 長く放置した、**When** 開く、**Then** 木は枯れず、成長係数が0.3まで下がっているだけ

### ストーリー4：樹形の評価を見る（P1）

プレイヤーとして、手入れの目安にするために、樹形の良さを点数で見たい。

**なぜこの優先度か**：手入れの良し悪しがわからないと、整える動機が続かない。

**受け入れシナリオ**
1. **Given** `age` が48未満、**When** 画面を見る、**Then** 右上に「まだ評価できません」と出る
2. **Given** `age` が48以上、**When** 手入れをする、またはステップが進む、**Then** 合計点・5指標の棒グラフ・呼び名が更新される

### ストーリー5：水墨画風の3Dビューで眺め、操作する（P1）

プレイヤーとして、眺めて心地よいように、和紙に墨で描いたような木を好きな角度から見たい。

**なぜこの優先度か**：見た目と操作感がゲームの魅力そのもの。手入れのクリック判定もこの画面に乗る。

**受け入れシナリオ**
1. **Given** 木が表示されている、**When** 右ドラッグ・ホイール・中ドラッグをする、**Then** 回転・ズーム・高さ移動ができ、R で正面に戻る
2. **Given** ツールを選んでいる、**When** 操作できる枝・葉・土にカーソルを乗せる、**Then** その対象だけが強調され、カーソルがツールごとに変わる
3. **Given** 節3,000個・葉4,000枚の木、**When** 一般的なノートPCで表示する、**Then** 30fps以上を保つ

### ストーリー6：木を保存し、別のブラウザへ移す（P1）

プレイヤーとして、育てた木を失わないように、自動で保存し、ファイルで持ち出したい。

**なぜこの優先度か**：1週間かけて育てる木が消えると、遊ぶ意味がなくなる。

**受け入れシナリオ**
1. **Given** 木を育てている、**When** ページを再読み込みする、**Then** 木の形・`age`・水分が元どおりに戻る
2. **Given** 書き出した JSON、**When** 別のブラウザで読み込む（確認メッセージに同意する）、**Then** 同じ木が表示される
3. **Given** 保存データの `version` が違う、または JSON が壊れている、**When** 起動する、**Then** 読み込まずに画面で知らせ、保存データは上書きしない
4. **Given** localStorage に書き込めない、**When** 手入れをする、**Then** 画面の端に警告が出て、遊び続けられる

### ストーリー7：完成を記録する（P3）

成木になったあと、日付とスコアを残したり画像で書き出したりする。v1 ではやらない（8.3 未決事項 → スコープ外）。

### ストーリー8：季節・複数の鉢・水やり通知（P3）

実際の季節の反映、複数の鉢、水やりの通知（PWA 化）。v1 ではやらない（スコープ外）。

### 5.1 成長と時間（ストーリー1）

| ID | 要件 | ストーリー |
|---|---|---|
| FR-001 | 保存データがない状態で起動したとき、土だけの鉢と「種をまく」ボタンを表示する。押したとき、32ビットの `seed` を作り、`age` 0 の種を植え、保存データを作る | 1 |
| FR-002 | 起動したとき、`floor((now − lastTickAt) / GROWTH_STEP_MS)` ステップを一括で進め、`lastTickAt` をそのステップ数 × `GROWTH_STEP_MS` だけ進める（端数は残す）。`GROWTH_STEP_MS` は 3,600,000 | 1 |
| FR-003 | `now − lastTickAt` が負のとき、ステップを進めず `lastTickAt` を `now` に直し、エラーを出さない | 1 |
| FR-004 | 1ステップで、水分 −4（0〜100に収める）→ 成長係数の決定 → 頂芽の伸長 → 側芽の分岐 → 太さの再計算 → 葉の付与・針金の形の維持 → `age` +1 をこの順に行う | 1 |
| FR-005 | 成長係数は `0.3 + 0.7 × water / 100`（水分0で0.3、100で1.0）とする（2026-10-25 確定）。葉の数が半分以下のときはさらに0.9倍する（FR-024） | 1, 3 |
| FR-006 | 1節の伸びは「段階の基準値 × 成長係数 × 乱数(0.8〜1.2)」とし、`age` が168を超えたら基準値を成木の値に固定する。枝先が伸びるかどうか・枝の向き・枝分かれの確率は ADR-0002 の仕組みに従う。数値は付録 A.2（2026-10-25 確定） | 1 |
| FR-007 | 段階は `age` で決まる：種 0／芽 1〜12／苗 13〜48／若木 49〜120／成木 121以上 | 1 |
| FR-008 | 乱数は `seed` から作る mulberry32 を使い、現在値 `rngState` を保存する。同じ `seed` に同じ手入れを同じ `age` で同じ順に行ったとき、節の一覧が完全に一致する | 1 |
| FR-009 | `seed` から4つの性格値（まっすぐさ・分岐しやすさ・枝の開き角・葉の大きさ、各0〜1）を決め、成長に反映する | 1 |
| FR-010 | 画面を開いている間は、次のステップまでの進み具合（0〜1）で伸びている節の長さを補間して描く。補間の値は保存しない | 1, 5 |
| FR-011 | タブが非表示の間は描画を止め、再表示したときに FR-002 の一括計算を行う | 1, 5 |
| FR-012 | 節が3,000個、または葉が4,000枚に達したら、それ以上の節・葉を増やさない | 1, 5 |
| FR-013 | URL に `?speed=N` があるとき、経過時間を N 倍として扱い、保存キーを `bonsai.save.v1.speed` に分ける（普段の木を早送りしない）。speed の木は閉じている間・タブが隠れている間は進めない（開いたときに `lastTickAt` を今の時刻に直す） | 1 |
| FR-014 | `window.__bonsai.advance(hours)` を呼んだとき、`hours` ステップをすぐに進める | 1 |

## 6. エッジケース・異常系

- 端末の時計が過去に戻った：成長を進めず `lastTickAt` を直すだけ（FR-003）
- 端末の時計を先に進めた：そのぶん成長する。個人利用なので許容（仮置き）
- 長期間放置（数週間）：起動時にすべてのステップをその場で計算する（上限なし）。節は上限（FR-012）で止まるので、1ステップの計算量も上限がある
- 水分0のまま放置：枯れない。成長係数0.3（FR-005）
- 幹の根元を切ろうとした：何もしない（FR-018）
- 太すぎる枝に針金：曲がらない（FR-019）【要確認：そのときの表示】
- 曲げすぎ：折れて剪定扱い（FR-022）
- 針金9本目：巻かない（FR-021）
- 水分100で水やり：変化なし、表示だけ（FR-025）
- Ctrl+Z をステップ後・2回連続で押した：何もしない（FR-027）
- 保存データの version 違い・壊れた JSON・形の不正なファイルの読み込み：読み込まず知らせ、上書きしない。保存データは、作者が選んだときだけ別キーに退避して種から始められる（FR-044、FR-047）
- `?speed` の木を閉じて翌日開いた：閉じている間は進めないので、早送りのまま一度に計算して固まることはない（FR-013）
- localStorage に書けない：警告を出して続ける（FR-045）
- Three.js やフォントの CDN に届かない：フォントは端末の明朝体で代替（FR-041）。Three.js が読めないときは、和紙の画面に「3D の部品を読み込めませんでした」と出し、成長と保存はそのまま動かす（2026-10-25 決定）
- 複数タブで同時に開いた：localStorage を互いに上書きしうる【要確認：対策するか（後から開いたタブを優先する、など）】
- `file://` で開いた場合と開発サーバーで開いた場合では localStorage が別になる。遊ぶときは `dist/index.html` を直接開く

## 7. 非機能要件

| 区分 | 要件 |
|---|---|
| 性能 | 60fps を目標。節3,000個・葉4,000枚で一般的なノートPCで30fps以上（SC-014） |
| セキュリティ | 個人情報は扱わない。読み込む JSON は外から来た値として、形と値の範囲を検証してから使う |
| コスト | 0円。サーバーなし。Three.js（CDN）と Webフォント（Google Fonts など）は無料・キー不要のものだけを使う |
| 対応環境 | PC版の最新の Chrome・Edge・Firefox。マウス＋キーボード。初回だけ Three.js とフォントの読み込みにネットワークが要る |
| 配布 | ビルド結果は `index.html` 1ファイル（スタイル・スクリプトを内包）。Three.js は版を固定して CDN から読む。公開はしない |
| 構成 | Rng・Clock・Tree・Evaluator・Store は Three.js・DOM に依存させず、Node 上で時間を進めて確かめられるようにする |
| 時刻 | 端末の時計をそのまま信頼する（仮置き） |

## 8. データ（主要エンティティ）

| エンティティ | 主な属性 | 関連 |
|---|---|---|
| 保存データ（SaveData） | `version`、`seed`、`rngState`、`createdAt`、`lastTickAt`、`age`、`water`、`traits`、`nextId` | 節を `nodes` に持つ |
| 性格値（Traits） | `straightness`、`branchiness`、`spread`、`leafSize`（各0〜1） | 保存データに1つ |
| 節（Node） | `id`、`parent`（根元は −1）、`pos`、`dir`、`length`、`radius`、`bornAge`、`bud`（頂芽の有無）、`boostUntil`（剪定の芽吹きブーストが切れる `age`）、`wire` | 親の節を `parent`（親の `id`）でたどる。葉を `leaves` に持つ |
| 針金（Wire） | `until`（外れる `age`）、`axis`（回転軸）、`angle`（その節で曲げた角度） | 節に0か1つ |
| 葉（Leaf） | `size`、`regrowAt`（摘んだあと生え直す `age`、なければ `null`） | 節に0個以上 |

形の例は付録 A.5。剪定のブースト（FR-017）・針金の中身・`id` の振り方（`nextId`）は ADR-0001（採択）で決めた。

## 付録：詳細仕様

作者の要件定義書から、実装の目安になる数値と式をそのまま残す。本文の FR と食い違ったら本文を正とし、ここを直す。

### A.1 時間

- 1ステップ = 3,600,000ミリ秒（`GROWTH_STEP_MS`）。成木までは168ステップ（約7日）
- 端数の時間は `lastTickAt` に残す。時刻はすべて UTC のミリ秒

### A.2 成長

| 段階 | age | 見た目 |
| --- | --- | --- |
| 種 | 0 | 土の上に種 |
| 芽 | 1〜12 | 双葉と短い茎 |
| 苗 | 13〜48 | 細い幹と最初の枝 |
| 若木 | 49〜120 | 幹が太くなり、枝が分かれていく |
| 成木 | 121〜 | 樹形がほぼ完成。以後は伸びがゆるやか |

- 枝の次数：幹 0、幹から出た枝 1、その先 2 以上。子のうち `id` が最も小さいものを延長、ほかを横枝とみなして求める（保存しない）
- 枝先の伸び（頂芽優勢の衰え。ADR-0002）：枝先は毎ステップ、次の確率で1節伸びる。伸びなかった枝先は頂芽を持ったまま

| 次数 | 芽 | 苗 | 若木 | 成木 |
| --- | --- | --- | --- | --- |
| 0（幹） | 1 | 0.55 | 0.2 | 0.03 |
| 1 | 1 | 0.7 | 0.3 | 0.04 |
| 2 以上 | 1 | 0.5 | 0.35 | 0.06 |

- 伸びの基準値（鉢の直径＝1）：芽 0.012、苗 0.014、若木 0.012、成木 0.008
- 向き：親の向きから乱数でずらす（大きさ 0.3 × (1 − straightness) ラジアン）。幹は上向きに偏らせ（y に +0.15）、枝は向きの y 成分を 0.3 へ 0.25 の割合で寄せる（水平より少し上）
- 分岐：生まれて 12 ステップ以内（剪定のブースト中はいつでも）で、子が1つ以下、かつ頂芽がもう伸びた節は、確率 `BRANCH_P × (0.5 + branchiness) × crowd` で横枝を出す。`BRANCH_P` は芽 0・苗 0.012・若木 0.003・成木 0.003。`crowd = (1 − 節の数 / 3000) / (1 + (節の数 / 500)²)`。開き角は `45° + spread × 35°`
- 太さ：子のない節を 0.003 とし、根元へ `r親 = √(Σ r子²) + 0.00003` で計算し直す
- 葉：枝先から 5 節未満の節にだけ、1節に 3 枚付く。枝が伸びて内側になった節の葉は落ちる（作者の回答 2026-10-21。節が上限に届いても枝先の葉は残る）
- 育ち方の目安：7日目（age 168）で節 150〜1,500 個。上限 3,000 に届くのは、枝分かれしやすい種でも 2週間以上あと（ADR-0002 の V-06）

### A.3 樹形評価の求め方（目安）

| 指標（各20点） | 求め方 |
| --- | --- |
| 先細り | 幹と各枝について、根元から先へ進んだときの太さが単調に減っている割合を20点に換算 |
| 幹の曲がり | 幹の中心線を等間隔に区切り、曲率が小さすぎず大きすぎない範囲にある割合と、曲がる向きが1回以上入れ替わっているか（緩やかなS字）で採点 |
| 枝の配置 | 幹から出る枝を高さ順に並べ、隣の枝との水平方向の角度差の平均が120〜150度に近いほど、高さの近い枝が少ないほど高得点 |
| 樹冠の輪郭 | 正面から見た影絵と、頂点が中心から幅の15〜30%ずれた三角形との重なり率（重なった面積 ÷ 合わせた面積）を20点に換算 |
| 葉の充実 | 枝先1本あたりの葉の数が3〜8枚にある枝の割合で採点 |

### A.4 見た目

2026-10-25 に実装し、作者が絵を見て確定した（数値は src/render/ の定数。.claude/plans/ink-render.md の「実装時の判断」）。鉢は成長の単位（鉢の直径＝1）より小さく描く（半径 0.32・深さ 0.16）。

| 要素 | 見せ方 | 実装の方針 |
| --- | --- | --- |
| 背景 | 和紙の色（生成り色）に、繊維のような淡いムラ | 画面全体にノイズを使った背景シェーダー。四隅をわずかに暗くする |
| 幹・枝 | 墨の濃淡。根元ほど濃く、枝先ほど淡い | 節ごとの円柱。光の当たり方を3段階に区切り、墨の濃度に割り当てる |
| 輪郭線 | 筆で引いたような、太さに強弱のある線 | 裏返した外殻を法線方向に少し膨らませて描く。線幅に節ごとの乱数を足す |
| 葉 | 淡い墨のしみが集まったような塊 | 小さな板に墨のにじみ模様を貼る。常にカメラを向く |
| 鉢と土 | 濃い灰色の簡素な鉢、乾き具合で色が変わる土 | 単純な形状。土は水分に応じて薄い茶灰から濃い茶灰 |
| 光 | 左上から1方向。影は落とさない | 影の計算を省く |
| 演出 | 伸びた部分が1秒かけてにじむ。切った枝は薄れながら落ちる | 節ごとの墨濃度を時間で補間 |
| 文字・UI | 明朝体。呼び名は朱色の印の四角の中 | Webフォント。読めなければ端末の明朝体 |
