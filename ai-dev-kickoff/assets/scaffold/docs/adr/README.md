# docs/adr — 設計判断の記録（ADR）

あとから「なぜこうなっているのか」を追えるように、設計判断を1件1ファイルで残す。

- **調査の段階から書き始める**。決まってから清書するのではなく、問いが立った時点でファイルを作り（状態：調査中）、AIの提案と検証の結果をその都度足していく
- **AIの提案は、検証するまで事実として扱わない**。提案と検証結果を分けて書き、検証で裏づけたものだけを決定の根拠にする
- **選ばなかった選択肢も残す**。理由と、何が変わったら戻る価値があるかを書く
- **コードから辿れるようにする**。決定を実装した箇所に `ADR-NNNN` と書き、ADR の側にもその箇所を書く

## いつ書くか

次のどれかに当たる判断は ADR にする。迷ったら書く（あとで「却下」にしてよい）。

- 選択肢が2つ以上あり、あとから変えるとコストが大きい（ライブラリ・DB・ホスティング・データ構造・認証方式・外部APIなど）
- AIが提案した方式を、動かして・調べて確かめる必要がある
- 要件やプランの【要確認】を、調査して決める
- 要件の解釈やトレードオフで、「なぜこっちにしたのか」を後で聞かれそうなもの

1つのプランの中で閉じる小さな判断は、プランの「判断済みの論点」に書けば足りる。

## ファイル

- `docs/adr/NNNN-<スラッグ>.md`。番号は 0001 からの通し番号で、使い回さない
- `_template.md` を複製して作る（`/adr <決めたいこと>`）
- 検証のために書いた使い捨てのコードは本体（src/）に混ぜない。残す価値があれば `docs/adr/spikes/NNNN/` に置き、検証ログから参照する

## 状態

| 状態               | 意味                                                   | 誰が変えるか |
| ------------------ | ------------------------------------------------------ | ------------ |
| 調査中             | 問いと選択肢を集め、検証している                       | AI・人間     |
| 提案               | 判定基準すべてに検証の根拠がそろい、AIが推奨を書いた   | AI・人間     |
| 採択               | 人間が決めた。これに基づいて実装してよい               | 人間のみ     |
| 却下               | どの選択肢も採らない／問い自体をやめた                 | 人間のみ     |
| 置換（ADR-NNNN）   | 後の ADR で決定が変わった                              | 人間のみ     |

- AIは「提案」までしか進めない。「採択」「却下」「置換」は人間が決め、AIはその指示を受けて書き込む
- 採択した ADR の「決定」は書き換えない。変えたいときは新しい ADR を立て、採択と同時に古いほうを「置換」にする
- 採択されていない ADR に基づいて実装しない

## 検証ログの書き方

- 1エントリ（V-01, V-02 …）＝ 1つの主張を1回確かめたこと
- 「AIの提案・主張」と「検証方法・結果」を分けて書く。提案したモデル名も書く
- 確かめ方の優先順：実際に動かす（小さなコード・コマンド）＞ 一次資料（公式ドキュメント・仕様・ソース。版と日付つき）＞ 二次資料
- 結果は出力をそのまま貼る。長ければ要点と、全文の置き場所を書く。「動いた」「問題なさそう」だけで済ませない
- 判定は「確認済み」「一部確認」「反証」「不明」のどれか。不明のときは、何があれば確かめられるかを書く
- **追記のみ**。過去のエントリを消したり直したりしない。誤りがわかったら新しいエントリで訂正し、どのエントリを訂正したかを書く

## 実装コードからの参照

ADR の決定を実装したコードには、その言語のコメントで `ADR-NNNN` と一言の要約を書く。

```ts
// ADR-0003: 座標は小数3桁に丸めてから送る（選ばなかった案と理由は docs/adr/0003-*.md）
```

- 書く場所は、決定がコードに現れる箇所に絞る（設定、境界のモジュール、あえて素直でない書き方をしている箇所）。関係するファイルすべてには書かない
- 参照を足したら、ADR の「実装箇所」にそのファイルを足す
- 参照の一覧は `grep -rnE "ADR-[0-9]{4}" <ソースのディレクトリ>` で出せる。ADR の「実装箇所」とずれていたら直す
- 置換・却下された ADR を参照しているコードは、新しい ADR に合わせて直すか、直さない理由を新しい ADR に書く
